프로젝트 디렉터리 준비

Codex는 채팅만 하는 도구가 아닙니다. 특정 프로젝트 디렉터리 안에서 작업합니다. 공식 시작 절차도 Codex에 로그인한 뒤 컴퓨터의 폴더나 Git 리포지토리를 선택하고 첫 번째 작업을 시작하는 방식입니다.

전용 연습 디렉터리를 미리 하나 만들어 두십시오. 예를 들면 다음과 같습니다.

D:\AI-Codex-Projects

그 안에 다음과 같은 프로젝트를 둘 수 있습니다.

hello-web
ai-tools-page
product-cover-tool
landing-page-demo

처음부터 Codex에 가장 중요한 실제 프로젝트를 맡기지 마십시오. 먼저 연습 프로젝트로 파일 수정, 명령 실행, 결과 생성 방식을 익히십시오.

권한과 보안 준비

Codex는 파일을 읽고 수정할 수 있으며, 프로젝트 디렉터리 안에서 명령도 실행합니다. CLI 공식 설명에도 사용자가 선택한 디렉터리에서 코드를 읽고 수정하며 명령을 실행할 수 있다고 되어 있습니다.

설치 전에 다음 사항에 주의하십시오.

주의할 점 권장 사항
중요 파일을 바로 넣지 마십시오 먼저 테스트 프로젝트를 사용하십시오
비밀번호/API Key를 코드에 쓰지 마십시오 .env 파일을 사용하고 업로드하지 마십시오
작업 전 먼저 Git 커밋을 하십시오 되돌리기 쉽습니다
Codex가 실행하려는 명령을 잘 확인하십시오 이해하지 못하는 명령은 먼저 설명해 달라고 하십시오
전체 C 드라이브 권한을 주지 마십시오 구체적인 프로젝트 폴더만 선택하십시오

각 프로젝트는 먼저 Git을 초기화하십시오.

git init
git add .
git commit -m "initial commit"

이렇게 해 두면 Codex가 잘못 수정하더라도 되돌릴 수 있습니다.

Codex App 설치와 시작하기(초보자에게 권장되며 기능도 가장 많습니다)

다운로드와 설치

macOS 설치

Mac을 사용한다면 먼저 칩 종류를 확인하십시오.

컴퓨터 왼쪽 위의 Apple 아이콘을 클릭하고 “이 Mac에 관하여”를 선택합니다.

다음과 같이 표시된다면:

  • Apple M1 / M2 / M3 / M4: Apple Silicon 버전을 선택합니다.
  • Intel: Intel 버전을 선택합니다.

Codex App 공식 페이지에서 본인의 칩에 맞는 버전을 다운로드합니다. 다운로드가 끝나면 설치 패키지를 열고 Codex를 “응용 프로그램” 폴더로 드래그합니다.

설치가 끝나면 “응용 프로그램”에서 Codex를 엽니다.

처음 열 때 시스템에서 다음 안내가 나올 수 있습니다.

“인터넷에서 다운로드한 앱입니다. 열겠습니까?”

“열기”를 선택합니다.

Intel Mac과 Apple Silicon의 차이

Mac은 주로 두 종류의 칩으로 나뉩니다.

유형 흔한 모델 다운로드할 버전
Apple Silicon M1 / M2 / M3 / M4 Mac Apple Silicon 버전
Intel Mac 구형 Intel 칩 Mac Intel 버전

가장 간단한 확인 방법입니다.

“이 Mac에 관하여”를 열고 칩 정보를 확인합니다.

Apple M 시리즈라고 쓰여 있으면 Apple Silicon입니다.

Intel Core i5, Intel Core i7, Intel Core i9라고 쓰여 있으면 Intel Mac입니다.

여기서 버전을 잘못 선택하지 마십시오. 잘못된 버전을 선택하면 설치되지 않거나, 열리지 않거나, 실행이 불안정해질 수 있습니다.

Windows 설치

Windows를 사용한다면 Codex App 공식 페이지에 들어가 Windows 버전을 선택합니다.

Windows 버전은 보통 Microsoft Store로 이동해 설치합니다.

설치 단계:

  1. Codex App 공식 페이지를 엽니다
  2. Windows 다운로드 항목을 클릭합니다

  1. Microsoft Store로 이동합니다

  1. “받기” 또는 “설치”를 클릭합니다(여기서는 이미 설치했으므로 열기로 표시됩니다)
  2. Codex App을 엽니다
  3. 여기까지 오면 Codex App 설치가 완료됩니다

프로젝트 디렉터리 선택

Codex App을 처음 열고 로그인을 마치면 프로젝트 디렉터리를 선택하라는 안내가 나옵니다.

여기서 “프로젝트 디렉터리”는 다음 뜻입니다.

Codex가 작업할 폴더입니다.

예를 들어 Codex가 웹페이지를 만들어 주길 원한다면 미리 새 폴더를 만듭니다.

hello-codex

그런 다음 Codex App에서 이 폴더를 선택합니다.

처음에는 깨끗한 연습 디렉터리를 선택하십시오. C 드라이브를 직접 선택하거나 처음부터 중요한 업무 프로젝트를 선택하지 마십시오.

권장 디렉터리 구조:

AI-Codex-Projects
└── hello-codex
    └── index.html

프로젝트 디렉터리를 선택해야 Codex가 어떤 파일을 읽고 수정할지, 어디에서 명령을 실행할지 알 수 있습니다.

프로젝트 목록 이해하기

Codex App에 들어가면 보통 왼쪽에 프로젝트 목록이 보입니다.

프로젝트 목록은 다음 뜻입니다.

Codex에 맡긴 서로 다른 코드 폴더입니다.

예:

hello-codex
ai-first-page

각 프로젝트는 컴퓨터의 로컬 폴더 하나 또는 Git 리포지토리 하나에 대응합니다.

이전에 Codex App, Codex CLI, Codex IDE Extension에서 프로젝트를 열어 본 적이 있다면 그 프로젝트들도 목록에 나타날 수 있습니다.

한 가지만 기억하십시오.

프로젝트 목록은 채팅 기록 목록이 아니라 “코드 프로젝트 목록”입니다.

서로 다른 프로젝트를 클릭하면 Codex가 볼 수 있는 파일 범위가 달라집니다.

thread(대화) 이해하기

Thread는 다음 뜻입니다.

같은 프로젝트 안에서 진행하는 하나의 작업 대화입니다.

예를 들어 hello-Codex 프로젝트 안에서 여러 thread를 열 수 있습니다.

Thread 1: 홈페이지 만들기
Thread 2: 버튼을 클릭해도 반응이 없는 문제 수정
Thread 3: 모바일 스타일 최적화
Thread 4: README 작성 도와주기

각 thread에는 자체 컨텍스트가 있습니다.

Thread 1에서 Codex에게 홈페이지를 만들라고 하면 이 작업을 중심으로 이해하고 수정합니다.

Thread 2에서 버그를 고치라고 하면 다른 작업을 중심으로 일합니다.

간단히 다음처럼 이해하면 됩니다.

  • 프로젝트 = 하나의 회사
  • thread = 회사 안의 직원

모든 작업을 같은 thread에 넣지 마십시오.

더 나은 방법은 다음과 같습니다.

명확한 작업 하나마다 thread를 하나 엽니다.

예:

개인 홈페이지를 만들어 주세요

이것은 하나의 thread입니다.

모바일 레이아웃이 왜 어긋나는지 확인해 주세요

이것은 또 다른 thread입니다.

이렇게 하면 프로젝트가 어지러워지지 않고 Codex도 작업 경계를 더 쉽게 이해합니다.

작업 창 이해하기

작업 창은 사용자가 Codex와 대화하고 일을 배정하는 곳입니다.

여기에 작업을 입력합니다. 예:

검은색 배경에 가운데 Hello, Codex가 표시되는 간단한 웹페이지를 만들어 주세요.

이어서 질문할 수도 있습니다.

이 페이지를 기술 제품 홈페이지처럼 더 바꿔 주세요.

작업 창에는 보통 다음 내용이 표시됩니다.

내용 역할
사용자의 작업 설명 Codex에게 무엇을 해야 하는지 알려 줍니다
Codex의 계획 어떻게 처리하려는지 보여 줍니다
Codex의 실행 과정 파일을 보고 수정하며 명령을 실행하는 과정입니다
Codex의 요약 마지막에 수정한 내용을 알려 줍니다
후속 입력창 계속 수정 요청을 입력합니다

처음 사용할 때는 너무 복잡한 작업을 입력하지 마십시오.

권장하지 않음:

로그인, 결제, 데이터베이스, 관리자 대시보드가 있는 완전한 AI 도구 플랫폼을 만들어 주세요.

권장:

HTML과 CSS만 사용해서 간단한 제품 소개 페이지를 만들어 주세요.

작업이 명확할수록 Codex가 처리하기 쉽습니다.

review pane 이해하기

Review pane은 다음 뜻입니다.

Codex가 수정한 내용을 확인하는 곳입니다.

Codex가 파일 수정을 마친 뒤에는 텍스트 요약만 보지 말고 review pane을 열어 실제 변경 사항을 확인하십시오.

여기에서는 다음을 확인합니다.

  • 어떤 파일이 수정되었는지
  • 어디에 코드가 추가되었는지
  • 어디에서 코드가 삭제되었는지
  • 어떤 변경을 수락할 수 있는지
  • 어떤 변경을 되돌릴 수 있는지

초보자는 review pane을 이렇게 이해하면 됩니다.

Codex의 “숙제 검사 구역”입니다.

Codex가 다 썼다고 해서 바로 믿지 말고, 여기서 실제로 어떤 결과를 제출했는지 확인하십시오.

어떤 코드 줄이 마음에 들지 않으면 해당 위치에 댓글을 남겨 Codex에 수정을 요청합니다.

예를 들어 다음처럼 댓글을 달 수 있습니다.

여기 버튼 색상이 너무 밝습니다. 더 절제된 짙은 파란색으로 바꿔 주세요.

또는:

이 코드는 너무 복잡합니다. 초보자가 더 이해하기 쉬운 방식으로 바꿔 주세요.
diff 이해하기

Diff는 코드 변경 사항을 비교한 내용입니다.

초보자는 다음처럼 이해하면 됩니다.

초록색 = 추가된 내용
빨간색 = 삭제된 내용

예를 들어 Codex가 원래 제목을 쓰지 않았는데 나중에 한 줄을 추가했다면 다음과 같습니다.

<h1>Hello, Codex</h1>

이 줄은 추가된 것으로 표시됩니다.

Codex가 기존 코드 일부를 삭제했다면 그 부분은 삭제로 표시됩니다.

Diff는 다음을 명확히 보여 줍니다.

Codex가 정확히 무엇을 바꾸었는지입니다.

최종 페이지만 보거나 Codex의 요약만 읽지 마십시오.

반드시 diff를 확인하십시오.

Codex가 때때로 다음과 같은 일을 할 수 있기 때문입니다.

  • 요청하지 않은 곳을 함께 수정함
  • 아직 필요한 코드를 삭제함
  • 간단한 코드를 복잡하게 만듦
  • 여러 파일을 수정했지만 명확히 설명하지 않음

처음부터 다음 습관을 들이십시오.

Codex가 작업을 완료할 때마다 먼저 diff를 보고, 그다음 수락할지 결정합니다.
처음 연 뒤 권장 작업 흐름

Codex App을 처음 열었다면 다음 순서로 작업하십시오.

1. ChatGPT에 로그인
2. 연습용 프로젝트 디렉터리 선택
3. thread를 새로 만들거나 선택

7. diff 확인

3. 흰색 글꼴
4. 전체 페이지를 가로와 세로로 가운데 정렬
5. HTML과 CSS만 사용

Codex App의 기본 사용

기본 레이아웃

Codex App은 전형적인 3열 레이아웃입니다.

왼쪽은 작업 목록입니다.

가운데는 대화 창입니다.

오른쪽은 다기능 영역입니다.

새 대화
프로젝트 사용

새 대화를 열어 새 작업을 실행합니다.

새 대화를 연 뒤에는 그 대화가 어느 프로젝트에 속하는지 선택해야 합니다.

프로젝트 오른쪽의 작은 버튼을 클릭해 해당 프로젝트의 새 대화를 바로 열 수도 있습니다.

프로젝트를 사용하지 않기

프로젝트를 사용하지 않음을 클릭하면 해당 세션이 대화 안에 표시됩니다. 프로젝트와 관련 없는 질문을 할 때 사용합니다.

검색

나중에 작업 대화가 너무 많고 몇 가지 키워드만 기억난다면 여기에서 검색하십시오. 키워드를 검색하면 해당 작업 대화를 찾을 수 있습니다.

프로젝트
프로젝트 만들기

Codex에서 새 프로젝트를 직접 만들 수도 있고 기존 프로젝트를 사용할 수도 있습니다.

만들거나 선택한 프로젝트는 프로젝트 열에 표시되어 나중에 관리하기 쉽습니다.

thread

thread는 프로젝트 안의 “별도 작업 대화”입니다.

예를 들어 다음과 같은 프로젝트가 있다고 가정합니다.

hello-codex

이 프로젝트 안에서 여러 thread를 열 수 있습니다.

Thread 대표하는 작업
Thread 1 홈페이지 만들기
Thread 2 버튼 클릭이 반응하지 않는 문제 수정
Thread 3 모바일 스타일 최적화
Thread 4 README 작성 도와주기
Thread 5 프로젝트에 오류가 있는지 확인

다음처럼 이해하면 됩니다.

Project = 하나의 코드 폴더
Thread = 이 프로젝트 안의 구체적인 작업 하나

예:

프로젝트: 샤오홍슈 커버 생성기
Thread 1: 홈페이지 만들기
Thread 2: 이미지 업로드 실패 수정
Thread 3: 모바일 레이아웃 최적화
Thread 4: 프로젝트 설명 문서 작성

왜 thread가 필요할까요?

서로 다른 작업은 나누어 처리하는 편이 좋습니다.

“홈페이지 만들기, 버그 수정, 스타일 변경, 문서 작성”을 한 대화에 모두 넣으면 Codex가 컨텍스트를 혼동하기 쉽고 사용자가 무엇을 바꾸었는지 확인하기도 어렵습니다.

더 나은 사용법은 다음과 같습니다.

명확한 작업 하나 = thread 하나

예를 들어 페이지를 만들고 싶다면:

AI 도구 소개 페이지를 만들어 주세요.

이것은 하나의 thread입니다.

나중에 버튼 문제를 발견하면 새 thread를 엽니다.

홈페이지 버튼을 클릭해도 왜 반응이 없는지 확인해 주세요.

한 문장으로 정리하면 다음과 같습니다.

Thread는 Codex App 안의 작업 대화이며, 하나의 thread는 하나의 구체적인 작업을 맡습니다.

승인 대기

Codex가 작업을 실행할 때는 사용자 권한 승인이 필요한 경우가 많습니다.

해당 대화에는 승인 대기 라벨이 표시됩니다.

해당 대화를 클릭한 뒤 허용을 클릭하면 Codex가 다음 작업을 계속 진행합니다.

아카이브

Archive는 이미 완료되어 당분간 처리할 필요가 없는 thread를 접어 두는 기능입니다.

코드를 삭제하거나 병합하는 기능이 아니라 작업 목록을 더 깔끔하게 만드는 기능입니다.

예를 들어 다음 작업들을 완료했다고 합시다.

Thread 1: 모바일 스타일 최적화
Thread 2: 홈페이지 만들기
Thread 3: 홈페이지 만들기

이 중 Thread 2와 Thread 3은 이미 완료되었고 Thread 1도 더 이상 사용할 계획이 없다면 아카이브합니다.

아카이브 후에는 현재 작업 목록의 자리를 차지하지 않아 프로젝트 화면이 더 깔끔해집니다.

아카이브 취소: 설정에서 아카이브된 대화를 찾아 다시 복원합니다

설정
남은 한도

여기에서 현재 계정의 한도, 속도 제한 또는 사용량을 볼 수 있습니다.

요금제, 워크스페이스, 모델, 버전에 따라 표시되는 제한이 다를 수 있습니다. 얼마나 사용할 수 있는지, 언제 복구되는지, 추가 한도를 구매할 수 있는지는 Codex 현재 화면과 공식 안내를 기준으로 합니다.

대화 창
권한 제어
샌드박스

권한 제어를 이해하려면 먼저 샌드박스 개념을 알아야 합니다.

다음처럼 이해하면 됩니다.

Codex는 울타리 안에서 일할 수 있지만, 울타리 밖으로 함부로 나가 사용자의 컴퓨터를 건드릴 수는 없습니다.

Codex App은 일반 채팅 도구가 아니라 파일을 읽고 수정하며 명령을 실행합니다. 그래서 작업 가능한 위치, 네트워크 사용 여부, 프로젝트 밖 파일 수정 여부를 제한하는 “울타리”가 필요합니다. 공식 문서에서 Codex의 sandbox 모드에는 read-only, workspace-write, danger-full-access 등이 있으며, 파일 시스템과 네트워크 접근 경계를 제어하는 데 사용됩니다.

간단히 말하면

프로젝트 폴더가 다음과 같다고 가정합니다.

D:\AI-Codex-Projects\hello-codex

샌드박스를 켜면 Codex는 보통 이 프로젝트 폴더 범위 안에서만 작업합니다. 예:

index.html을 볼 수 있음
style.css를 수정할 수 있음
npm run dev를 실행할 수 있음

다음 작업에는 사용자 승인이 필요한 경우가 있습니다.

프로젝트 밖의 파일 수정
인터넷에서 무언가 다운로드
고위험 명령 실행

정리하면 다음과 같습니다.

승인 요청

다음처럼 대응해서 보면 됩니다.

표시되는 옵션 Sandbox와의 관계
승인 요청 샌드박스 제한이 있으며 경계를 넘는 작업은 먼저 사용자에게 묻습니다
대신 승인 시스템이 일부 승인을 자동으로 판단합니다
전체 접근 권한 샌드박스 제한을 풀어 컴퓨터에서 모든 작업을 실행할 수 있으며, 위험이 가장 높습니다

초보자는 다음을 켜는 편이 좋습니다.

승인 요청 또는 자동 승인 계열 옵션. 처음에는 프로젝트 경계를 열지 않는 모드를 선택하십시오. Codex가 현재 프로젝트 안에서는 작업할 수 있게 하되, 경계를 넘거나 네트워크를 사용하거나 고위험 명령을 실행할 때는 멈추고 사용자에게 확인하게 하는 방식입니다. 버전에 따라 권한 옵션 이름은 다를 수 있지만 핵심 원칙은 같습니다. 처음부터 전체 접근 권한을 켜지 마십시오.

추론 강도

추론 강도는 4단계입니다. 강도가 높을수록 추론 능력은 강해지지만 시간과 token 소모도 커집니다.

옵션 간단히 말하면 적합한 작업
낮음 덜 생각하고 빠르며 한도를 아낍니다 문구 수정, 색상 변경, 작은 문제
중간 속도와 품질의 균형 일반 웹페이지, 간단한 bug, 일상 개발
높음 더 깊게 생각하며 복잡한 문제에 적합합니다 여러 파일 수정, 복잡한 bug, 리팩터링
매우 높음 가장 신중하고 가장 느리며 가장 많이 소모합니다 매우 어려운 문제, 아키텍처 분석, 반복해도 잘 고쳐지지 않는 bug
모델 선택

여기에서 모델을 선택합니다. 모델 능력, 사용 가능 범위, 소모량은 계정 요금제, 지역, 버전, 모델 목록에 따라 바뀝니다. 일반 작업은 기본 추천 모델을 사용하면 됩니다. 복잡한 작업은 더 강한 모델로 전환하거나 추론 강도를 높이는 것을 고려하십시오.

속도

일부 모델이나 버전은 표준 / 빠름 같은 서비스 단계를 제공합니다.

빠른 모드의 속도 향상, 한도 소모, 사용 가능 여부는 현재 화면에 표시되는 내용을 기준으로 합니다. 작업이 매우 급하고 한도가 충분할 때 켜는 것을 고려할 수 있으며, 일상 작업에서는 기본으로 켤 필요가 없습니다.

안내

작업 중간에 안내를 추가합니다.

AI가 실행 중에 사용자의 의도를 잘못 이해했다면 계속 실행하게 두지 마십시오. 이때는 사람이 즉시 안내해야 합니다.

안내를 선택하지 않으면 요청이 대기열에 들어갑니다. 이전 작업이 끝난 뒤에야 AI가 사용자가 보낸 다음 작업을 실행합니다.

계획 모드

계획 모드를 켜면 Codex가 즉시 작업을 시작하지 않습니다. 먼저 작업 계획을 정리하고 사용자의 확인을 받은 뒤 시작합니다.

복잡한 작업은 먼저 계획 모드를 켜십시오. 빠진 부분을 확인하고 보완합니다.

다기능 영역
주석

주석은 다기능 영역 오른쪽 위에 있습니다.

Codex 내장 브라우저로 페이지를 열면 주석 기능이 보입니다.

이 기능으로 AI가 페이지의 특정 부분만 수정하도록 지시합니다.
