CLI 작동 방식

Codex CLI의 작동 방식은 다음 흐름으로 볼 수 있습니다.

프로젝트 읽기
→ 작업 이해하기
→ 계획 제안하기
→ 파일 수정하기
→ 명령 실행하기
→ 승인 기다리기
→ diff 보여주기
→ 실패 처리하기

초보자는 처음부터 모든 기술 세부 사항을 이해할 필요가 없습니다. 먼저 이것만 알면 됩니다.

Codex CLI는 단순한 채팅 도구가 아닙니다. 실제로 현재 프로젝트 디렉터리에서 파일을 읽고 수정하며 명령을 실행한 다음, 사용자가 확인할 수 있도록 결과를 보여 줍니다.

Codex가 프로젝트를 읽는 방식

프로젝트 디렉터리에서 다음을 실행하면:

codex

Codex는 현재 디렉터리를 워크스페이스로 봅니다.

예를 들어 이 디렉터리에서 시작하면:

D:\AI-Codex-Projects\hello-codex

Codex는 이 폴더의 내용을 기준으로 작업합니다.

다음 항목을 읽을 수 있습니다.

내용 역할
프로젝트 파일 현재 코드 이해
폴더 구조 프로젝트가 프런트엔드, 백엔드, 스크립트 프로젝트 중 무엇인지 판단
package.json 시작 명령, 의존성, 프로젝트 유형 판단
README.md 프로젝트 설명 이해
AGENTS.md 사용자가 Codex에 작성해 둔 작업 규칙 읽기
오류 로그 문제 원인 분석
Git 상태 어떤 파일이 변경되었는지 판단

기준은 다음과 같습니다:

어떤 폴더에서 Codex를 시작하든,
Codex는 기본적으로 그 폴더를 현재 프로젝트로 간주합니다.

다음 위치에서는 함부로 시작하지 마세요.

C:\
바탕 화면
다운로드 폴더
시스템 디렉터리
중요 자료 폴더

권장 방식:

cd 프로젝트-디렉터리
codex
Codex가 작업을 이해하는 방식

작업을 입력하면 Codex는 먼저 사용자가 무엇을 요청했는지 판단합니다.

예를 들어 다음을 입력하면:

검은색 배경에 가운데 Hello Codex가 표시되는 간단한 웹 페이지를 만들어 주세요.

Codex는 다음을 판단합니다.

이해하는 내용 예시
작업 유형 새 웹 페이지 만들기
수정 범위 현재 프로젝트 파일
필요할 수 있는 파일 index.html, style.css
명령 실행이 필요한지 여부 간단한 HTML은 필요하지 않을 수도 있음
위험이 있는지 여부 위험이 비교적 낮음

다음을 입력하면:

npm run build가 왜 실패하는지 확인해 주세요.

Codex는 다음을 판단합니다.

이해하는 내용 예시
작업 유형 빌드 실패 조사
실행해야 할 수 있는 명령 npm run build
읽어야 할 수 있는 파일 package.json, 오류와 관련된 파일
코드 수정이 필요한지 여부 필요할 수 있음
사용자 승인이 필요한지 여부 권한 설정에 따라 다름

초보자 팁:

작업이 명확할수록 Codex가 더 안정적으로 동작합니다.

권장 작성 방식:

[구체적인 작업]을 완료해 주세요.

요구사항:
1.
2.
3.

제한사항:
1. 관련 없는 파일은 수정하지 마세요
2. 기존 기능은 삭제하지 마세요
3. 완료 후 어떤 파일을 수정했는지 알려 주세요
Codex가 계획을 제안하는 방식

복잡한 작업을 시작하기 전에 Codex는 보통 먼저 문제를 분석한 다음 계획을 제안합니다.

사용자가 먼저 계획을 요청할 수도 있습니다.

먼저 계획을 제시해 주세요. 파일은 바로 수정하지 마세요.

또는 다음을 사용할 수 있습니다.

/plan

계획에는 보통 다음이 포함됩니다.

내용 역할
어떤 파일을 확인할 예정인지 프로젝트를 불필요하게 훑는 일을 방지
어떻게 수정할 예정인지 수정 방향을 먼저 확인
어떤 명령을 실행할 수 있는지 위험을 미리 확인
어떤 부분에 영향을 줄 것으로 예상하는지 수락 여부 판단에 도움

예:

계획:
1. 먼저 package.json을 확인해 시작 명령을 확인합니다
2. npm run build를 실행해 오류를 재현합니다
3. 오류를 바탕으로 관련 파일을 찾습니다
4. 최소 범위로 문제를 수정합니다
5. build를 다시 실행해 검증합니다

초보자 조언:

간단한 작업은 바로 시켜도 됩니다.
복잡한 작업은 먼저 /plan을 요청하세요.

다음 작업은 먼저 계획하는 편이 좋습니다.

복잡한 bug 수정
여러 파일 수정
프로젝트 리팩터링
새 기능 추가
빌드 실패
의존성 업그레이드 관련 작업
Codex가 파일을 수정하는 방식

Codex가 파일 수정이 필요하다고 판단하면 현재 프로젝트 안에서 편집합니다.

다음 작업을 할 수 있습니다.

작업 예시
새 파일 만들기 index.html 새로 만들기
파일 수정 style.css 수정
코드 삭제 사용하지 않는 코드 삭제
파일 이름 변경 파일명 조정
파일 분리 코드를 여러 모듈로 분리

초보자는 주의해야 합니다.

Codex가 올바르게 수정할 수도 있지만, 너무 많이 수정할 수도 있습니다.

다음 습관을 들이세요.

수정이 끝났다고 바로 믿지 마세요.
반드시 diff를 확인하세요.

미리 제한을 추가할 수 있습니다.

index.html과 style.css만 수정하고, 다른 파일은 수정하지 마세요.

또는:

문제를 최소 변경으로 수정하고, 전체 프로젝트를 리팩터링하지 마세요.

이렇게 하면 Codex가 지나치게 넓은 범위를 수정하는 문제를 줄일 수 있습니다.

Codex가 명령을 실행하는 방식

Codex는 파일 수정뿐 아니라 터미널 명령도 실행할 수 있습니다.

일반적인 명령은 다음과 같습니다.

명령 역할
npm install 의존성 설치
npm run dev 개발 프로젝트 시작
npm run build 프로젝트가 빌드되는지 확인
npm test 테스트 실행
git status Git 상태 확인
git diff 코드 변경 확인

예를 들어 빌드 실패를 고치라고 하면 다음을 실행할 수 있습니다.

npm run build

그런 다음 오류 내용을 기준으로 계속 수정합니다.

초보자는 명령을 피할 필요는 없지만, 이해한 뒤 허용해야 합니다.

이해하지 못했다면 먼저 설명을 요청할 수 있습니다.

실행하려는 명령을 먼저 설명해 주세요. 각 명령이 무엇을 하는지 알려 주고, 바로 실행하지 마세요.

다음 명령은 특히 신중하게 확인하세요.

rm -rf
sudo
curl xxx | sh
git reset --hard
git clean -fd

이 명령들은 파일을 삭제하거나, 시스템을 수정하거나, 코드를 초기화하거나, 원격 스크립트를 실행할 수 있습니다.

Codex가 사용자 승인을 기다리는 방식

Codex CLI에는 권한 제어가 있어 모든 작업이 바로 실행되지는 않습니다.

Codex가 민감한 작업을 하려면 멈춘 뒤 사용자에게 물어볼 수 있습니다.

예:

작업 승인이 필요할 수 있는 이유
인터넷으로 의존성 설치 외부 코드를 다운로드할 수 있음
프로젝트 밖 파일 접근 현재 워크스페이스를 벗어남
외부 파일 수정 다른 프로젝트에 영향을 줄 수 있음
고위험 명령 실행 내용을 삭제하거나 덮어쓸 수 있음
더 높은 권한 사용 위험이 더 큼

승인 의미:

승인 = Codex가 이 단계를 계속하도록 허용합니다.
거절 = 이 단계를 수행하지 않습니다.

무엇을 하려는지 이해하지 못했다면 바로 허용하지 마세요.

먼저 이렇게 물어볼 수 있습니다.

이 작업의 역할과 위험, 더 안전한 대안이 있는지 설명해 주세요.

초보자 권장 권한:

승인 요청을 유지하세요.
전체 접근 권한을 함부로 켜지 마세요.
Codex가 diff를 보여 주는 방식

Diff는 Codex가 수정하기 전과 후의 코드를 비교한 결과입니다.

Codex CLI에서 다음을 입력할 수 있습니다.

/diff

현재 변경 사항을 보여 줍니다.

색상 의미:

초록색 = 추가된 내용
빨간색 = 삭제된 내용

diff에서 다음을 확인합니다.

확인 지점 봐야 할 것
올바른 파일이 수정되었는지 관련 없는 파일까지 수정했는지
중요한 코드가 삭제되었는지 빨간색 삭제 부분을 중점적으로 확인
복잡한 의존성이 추가되었는지 불필요한 패키지를 더 설치했는지
변경이 너무 큰지 작은 작업이 큰 리팩터링이 되지 않았는지
요구사항에 맞는지 요청한 효과가 구현되었는지

권장 흐름:

Codex가 수정 완료
→ /diff 입력
→ 변경 사항 확인
→ 만족하지 않으면 계속 수정하거나 되돌리라고 요청
→ 만족하면 그때 git commit

Codex의 요약만 보지 마세요.

중요한 것은:

실제로 무엇을 수정했는지입니다.
Codex가 실패를 처리하는 방식

Codex는 작업 실행 중 실패할 수 있습니다.

일반적인 실패는 다음과 같습니다.

실패 유형 예시
명령 실패 npm run build 오류 발생
의존성 누락 어떤 패키지가 설치되지 않음
코드 오류 빈 페이지, 함수 오류
권한 부족 인터넷 또는 파일 접근 권한 없음
요구사항 오해 원하지 않는 방식으로 수정함
수정 범위가 너무 큼 관련 없는 파일까지 함께 수정함

Codex는 보통 실패 결과를 바탕으로 계속 분석합니다.

예:

npm run build 실행 실패
→ 오류 정보 읽기
→ 관련 파일 찾기
→ 코드 수정
→ build 다시 실행

주의할 점입니다.

끝없이 무작정 시도하게 두지 마세요.

연속해서 실패하면 잠시 멈추게 한 뒤 다시 분석을 요청하세요.

잠깐 멈춰 주세요. 현재 실패 원인을 요약하고, 파일 수정을 계속하지 마세요.

또는:

이미 시도한 방법, 실패 원인, 다음 단계의 최소 변경 방안을 나열해 주세요.

수정이 엉망이 되었다면 이렇게 요청하세요.

방금 수정한 내용을 되돌리고, 수정 전 상태로 복원해 주세요.

또는 Git으로 직접 확인하세요.

git status
git diff

그다음 유지할지 결정하세요.

초보자 권장 워크플로
단계 작업 목적
1 cd 프로젝트-디렉터리 올바른 프로젝트로 들어가기
2 Codex Codex CLI 시작
3 작업 입력 Codex에 무엇을 해야 하는지 알려 주기
4 복잡한 작업은 먼저 /plan 먼저 방안 확인
5 Codex가 프로젝트를 읽을 때까지 기다리기 컨텍스트를 이해하게 하기
6 민감한 작업 승인 이해한 뒤 허용하기
7 파일 수정이 끝날 때까지 기다리기 작업 실행
8 명령 실행으로 확인 결과 검증
9 /diff 변경 사항 확인
10 만족하지 않으면 계속 수정 반복 개선
11 만족 후 git commit 버전 저장
한 문장 요약

Codex CLI의 작동 방식은 "한 번 묻고 한 번 답하는" 것이 아니라, 하나의 완전한 프로그래밍 흐름입니다.

프로젝트 읽기
→ 방안 생각하기
→ 파일 수정하기
→ 명령 실행하기
→ 승인 기다리기
→ diff 보기
→ 실패 고치기
→ 결과 전달하기

CLI 자주 묻는 문제

Codex CLI에서 자주 발생하는 문제 대부분은 Codex 자체 고장보다 다음 지점에서 생깁니다.

초보자가 가장 자주 겪는 문제
문제 일반적인 원인 해결 방법
codex를 입력해도 반응이 없음 Codex가 제대로 설치되지 않았거나 명령이 환경 변수에 추가되지 않음 먼저 codex --version을 실행해 확인
command not found가 표시됨 터미널이 Codex 명령을 찾지 못함 Codex CLI를 다시 설치하거나 터미널을 다시 열기
어디서 Codex를 실행해야 할지 모름 프로젝트 디렉터리로 들어가지 않음 먼저 cd 프로젝트-디렉터리를 한 뒤 Codex 실행
Codex가 잘못된 프로젝트를 읽음 잘못된 폴더에서 시작함 종료한 뒤 올바른 프로젝트 디렉터리로 들어가 다시 시작
로그인 실패 브라우저가 열리지 않음, 네트워크 문제, 계정 미로그인 codex login으로 다시 로그인
API Key 로그인 실패 Key가 설정되지 않았거나, Key가 틀렸거나, 환경 변수가 적용되지 않음 환경 변수를 다시 설정한 뒤 로그인
Codex가 계속 기다림 권한 승인을 기다리는 중일 수 있음 터미널에 approval 프롬프트가 있는지 확인
Codex가 인터넷에 연결할 수 없음 샌드박스 또는 권한 제한 인터넷이 필요할 때 수동으로 승인
수정 후 무엇이 바뀌었는지 모름 diff를 보지 않음 Codex에서 /diff 입력
망가졌다면 어떻게 하나요? 미리 Git으로 저장하지 않음 git diff로 확인하고 필요하면 revert
설치 관련 문제
문제 원인 해결 방법
codex --version에 출력이 없음 Codex 설치가 성공하지 않음 Codex CLI 다시 설치
codex: command not found 명령이 PATH에 추가되지 않음 터미널을 다시 열거나 재설치
npm 설치 실패 Node.js / npm이 제대로 설치되지 않음 먼저 node -v와 npm -v 실행
Windows 설치 후 명령을 찾을 수 없음 PowerShell이 환경 변수를 새로고침하지 않음 터미널을 닫고 다시 열기
버전이 너무 오래됨 Codex CLI가 업데이트되지 않음 codex update 실행 또는 재설치

문제 확인 명령:
