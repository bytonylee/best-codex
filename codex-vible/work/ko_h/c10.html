코드 관리(Git 및 GitHub 워크플로)

Codex로 실제 프로젝트를 진행할 때는 Git과 GitHub의 기본 개념을 이해해야 합니다.

초보자는 먼저 이렇게 생각하면 됩니다.

Git = 로컬 코드 버전 관리 도구
GitHub = 코드를 온라인에 올려 협업하는 플랫폼
Codex = 코드를 읽고, 수정하고, 명령을 실행하도록 도와주는 AI 프로그래밍 도우미

한 문장으로 정리하면 다음과 같습니다.

Git은 코드 변경 사항을 기록합니다.
GitHub는 원격 저장과 협업을 담당합니다.
Codex는 구체적인 프로그래밍 작업을 완료하도록 도와줍니다.

Git Worktree

같은 Git 프로젝트에 독립적인 작업 복사본을 하나 더 엽니다.

스크래치패드처럼 쓰고, 결과가 만족스러우면 공식 프로젝트로 다시 병합합니다.

Worktree가 필요한 이유

일반 Git 브랜치는 전환할 수 있지만, 한 폴더에서는 한 번에 하나의 브랜치만 작업합니다.

Worktree는 이런 경우에 유용합니다.

상황 Worktree의 역할
Codex가 큰 폭으로 코드를 수정하게 하고 싶습니다 Codex에게 별도 복사본을 줍니다
현재 프로젝트에 영향을 주고 싶지 않습니다 메인 프로젝트는 그대로 유지합니다
여러 작업을 동시에 하고 싶습니다 작업마다 worktree 하나를 사용합니다
여러 방안을 비교하고 싶습니다 방안 A / B / C를 따로 둡니다
잘못 수정되어 필요 없습니다 worktree를 삭제합니다
큰 수정 / 리팩터링을 합니다 메인 프로젝트에 영향을 줄 위험을 줄입니다

# AGENTS.md

## 프로젝트 설명

이 프로젝트는 제품 페이지, 도구 페이지 또는 개인 포트폴리오 페이지를 만들기 위한 프런트엔드 웹 프로젝트입니다.

## 기술 스택

- React
- Vite
- Tailwind CSS
- JavaScript / TypeScript

## 자주 쓰는 명령

- 의존성 설치: `npm install`
- 프로젝트 시작: `npm run dev`
- 프로젝트 빌드: `npm run build`

## 프로젝트 구조

- `src/`: 주요 소스 코드
- `src/components/`: 공통 컴포넌트
- `src/pages/`: 페이지 파일
- `src/assets/`: 이미지, 아이콘 등 정적 리소스
- `public/`: 공개 정적 파일

AI로 프로그래밍할 때 흔한 걱정은 AI가 무작정 무언가를 삭제하는 일입니다. 다음 지침을 사용하세요.

파일이나 디렉터리를 일괄 삭제하지 마세요.

다음을 사용하지 마세요.

  • del /s
  • rd /s
  • rmdir /s
  • Remove-Item -Recurse
  • rm -rf

파일을 삭제할 때는 한 번에 명확한 경로의 파일 하나만 삭제하세요.

올바른 예:

Remove-Item "C:\path\to\file.txt"

파일을 일괄 삭제해야 한다면 작업을 중지하고 사용자에게 직접 삭제해 달라고 요청하세요.
