MCP

고급 AI 프로그래밍을 할 때만 알면 됩니다. 일반 사용자는 바로 건너뛰어도 됩니다.

Codex가 외부 도구에 연결할 때 쓰는 인터페이스입니다.

Codex 자체는 코드를 읽고 수정하며 명령을 실행합니다.

MCP는 Codex를 더 많은 외부 도구, 데이터 소스 또는 서비스에 연결합니다.

MCP란 무엇인가요?

개념 쉽게 말하면
MCP 외부 도구를 연결하는 표준 인터페이스
MCP Server 도구 기능을 제공하는 서비스
Tool Codex가 호출할 수 있는 구체적인 기능
Config MCP 설정 파일
STDIO Server 로컬 명령으로 시작되는 MCP 서비스
HTTP Server URL을 통해 연결되는 MCP 서비스
Context 외부 도구가 Codex에 제공하는 컨텍스트

간단한 비유로 보면 다음과 같습니다.

Codex = 일을 할 줄 아는 사람
MCP = 그 사람에게 여러 도구를 연결해 주는 콘센트
MCP Server = 콘센트에 꽂힌 도구 상자
Tool = 도구 상자 안의 구체적인 도구

예를 들어 문서 MCP를 쓰면 Codex가 문서를 읽습니다.

데이터베이스 MCP를 쓰면 Codex가 데이터베이스를 쿼리합니다.

디자인 도구 MCP를 쓰면 Codex가 디자인 시안 정보를 가져옵니다.

MCP는 어디에 적합한가요?

시나리오 MCP 사용 방법
개발 문서 조회 문서 MCP를 연결해 Codex가 새 버전 API를 조회합니다
데이터베이스 연결 Codex가 데이터베이스 구조나 테스트 데이터를 쿼리합니다
디자인 도구 연결 Codex가 디자인 시안과 컴포넌트 정보를 읽습니다
프로젝트 관리 도구 연결 issue, 작업, 요구사항 설명을 읽습니다
내부 시스템 연결 회사 내부 도구나 데이터 소스를 호출합니다
지식 베이스 연결 Codex가 팀 문서를 기준으로 작업합니다
자동화 도구 연결 Codex가 추가 스크립트나 서비스를 호출합니다

초보자는 이렇게 판단하면 됩니다.

일반적인 코드 작성에는 MCP가 꼭 필요하지는 않습니다.
Codex가 외부 도구나 외부 데이터에 접근해야 할 때만 MCP를 고려하면 됩니다.

MCP Server란 무엇인가요?

MCP Server는 이렇게 이해하면 됩니다.

Codex에 도구 기능을 제공하는 서비스입니다.

예시는 다음과 같습니다.

MCP Server 유형 제공할 수 있는 것
문서 MCP 개발 문서와 API 문서 조회
데이터베이스 MCP 테이블 구조 조회, 테스트 데이터 읽기
GitHub MCP issue, PR, 리포지토리 정보 읽기
Figma MCP 디자인 시안 정보 읽기
Notion MCP 지식 베이스 페이지 읽기
브라우저 MCP 웹페이지 방문 및 페이지 정보 읽기
내부 도구 MCP 회사 자체 시스템에 연결

쉽게 말하면 다음과 같습니다.

MCP Server = Codex가 호출할 수 있는 외부 도구 서비스입니다.

Codex App에서 MCP를 사용하는 방법

Codex App에서 MCP를 사용하는 기본 흐름
단계 작업 쉽게 말하면
1 Codex App 열기 데스크톱 버전 Codex를 엽니다
2 Settings로 이동 설정을 엽니다
3 MCP servers 찾기 MCP 도구 관리 영역을 엽니다
4 recommended servers 확인 공식 또는 시스템 추천 MCP를 확인합니다
5 custom server 추가 직접 만든 MCP server를 추가합니다
6 안내에 따라 권한 부여 완료 일부 MCP는 외부 계정 로그인이 필요합니다
7 프로젝트 thread로 돌아가기 작업에서 MCP를 사용합니다
8 결과와 권한 요청 확인 Codex가 호출한 도구를 확인합니다

MCP를 추가할 때 보통 입력해야 하는 것
설정 항목 역할 쉽게 말하면
Name MCP 이름 이 도구에 붙일 이름입니다
Command / URL 시작 명령 또는 서비스 주소 Codex가 이 값으로 도구에 연결합니다
Type MCP 유형 로컬 명령형 또는 원격 HTTP형
Env 환경 변수 token과 설정 항목을 넣습니다
Auth 권한 부여 방식 외부 계정 로그인이 필요한지 여부입니다
Enabled tools 활성화할 도구 필요한 기능만 켭니다

MCP를 추가한 뒤 사용하는 방법

추가한 뒤 Codex App의 thread로 돌아가 작업을 직접 설명합니다.

사용법 예시
요구사항을 직접 설명 Next.js App Router의 최신 사용법을 조회해 주세요
MCP 사용을 명확히 요청 사용 가능한 MCP 도구로 이 라이브러리의 문서를 조회해 주세요
특정 MCP 지정 context7로 Next.js의 최신 문서를 조회해 주세요
먼저 사용 가능한 도구 확인 현재 사용할 수 있는 MCP 도구에는 무엇이 있나요?

예시 프롬프트:

사용 가능한 MCP 문서 도구를 사용해
Next.js App Router의 최신 사용법을 조회한 뒤,
현재 프로젝트를 어떻게 수정해야 하는지 알려 주세요.

또는:

Figma MCP로 이 디자인 시안을 읽고,
페이지 구조를 분석한 다음 프런트엔드 구현 계획을 생성해 주세요.

Codex CLI에서 MCP를 사용하는 방법

Codex CLI에서 MCP를 사용한다는 뜻은 다음과 같습니다.

터미널 버전 Codex에 외부 도구를 연결합니다.

예시는 다음과 같습니다.

문서 MCP: Codex가 개발 문서를 조회하게 합니다
GitHub MCP: Codex가 issue, PR, 리포지토리 정보를 읽게 합니다
Figma MCP: Codex가 디자인 시안을 읽게 합니다
데이터베이스 MCP: Codex가 데이터베이스 구조를 쿼리하게 합니다

초보자는 이렇게 이해하면 됩니다.

Codex CLI = 터미널 안의 AI 프로그래밍 도우미
MCP = Codex CLI에 외부 도구를 연결하는 인터페이스
CLI에서 MCP를 사용하는 기본 흐름
단계 작업 쉽게 말하면
1 터미널 열기 PowerShell / Terminal
2 프로젝트 디렉터리로 이동 Codex가 현재 프로젝트를 인식하게 합니다
3 MCP server 추가 Codex에 외부 도구를 연결합니다
4 MCP가 추가됐는지 확인 도구를 사용할 수 있는지 확인합니다
5 Codex CLI 시작 Codex 대화 화면을 엽니다
6 /mcp로 도구 확인 현재 사용할 수 있는 MCP를 확인합니다
7 작업에서 MCP 호출 Codex가 외부 도구를 사용합니다
8 결과와 권한 안내 확인 안전한지 확인합니다
자주 쓰는 MCP 터미널 명령
명령 역할 쉽게 말하면
codex mcp --help MCP 명령 도움말 보기 사용법을 모를 때 먼저 확인합니다
codex mcp list 설정된 MCP server 보기 현재 연결된 외부 도구를 확인합니다
codex mcp add MCP server 추가 Codex에 외부 도구를 추가합니다
codex mcp remove MCP server 삭제 더 이상 쓰지 않으면 제거합니다
codex mcp get 특정 MCP server 상세 정보 보기 구체적인 설정을 확인합니다
codex mcp login 권한 부여가 필요한 MCP에 로그인 일부 원격 MCP에 권한을 부여합니다
codex mcp logout 특정 MCP 권한에서 로그아웃 연결 상태를 해제합니다
/mcp Codex 세션에서 MCP 보기 현재 세션에서 호출할 수 있는 도구를 확인합니다
MCP를 추가하는 기본 형식

MCP를 추가할 때 보통 다음 명령을 사용합니다.

codex mcp add 이름 -- 시작-명령

쉽게 말하면 다음과 같습니다.

이름 = 이 MCP에 붙이는 이름
시작명령 = 이 MCP를 시작하는 방법

예시:

codex mcp add context7 -- npx -y @upstash/context7-mcp

이 명령은 다음 뜻입니다.

Codex에 context7이라는 MCP를 추가합니다.
npx를 통해 @upstash/context7-mcp 도구를 시작합니다.
이미 추가한 MCP 확인하기

추가한 뒤에는 다음을 실행합니다.

codex mcp list

역할:

현재 Codex CLI에 어떤 MCP server가 설정되어 있는지 봅니다.

방금 추가한 이름이 보이면 설정이 저장된 것입니다.

Codex 시작 후 MCP 확인하기

먼저 프로젝트 디렉터리로 이동합니다.

cd 프로젝트-디렉터리

그다음 Codex를 시작합니다.

codex

Codex CLI가 시작되면 다음을 입력합니다.

/mcp

역할:

현재 세션에서 사용할 수 있는 MCP 도구를 봅니다.

MCP가 표시되지 않으면 다음 이유를 확인합니다.

문제 가능한 원인
추가되지 않음 codex mcp add 명령이 실패했습니다
MCP 시작 실패 의존성이 설치되지 않았거나 명령이 잘못되었습니다
이름을 잘못 씀 호출할 때 server 이름을 잘못 입력했습니다
권한 부여 필요 아직 외부 서비스에 로그인하지 않았습니다
설정이 새로고침되지 않음 Codex CLI를 다시 시작해야 합니다
작업에서 MCP 호출하기

MCP를 설정한 뒤에는 복잡한 명령을 기억할 필요가 없습니다.

Codex CLI에서 이렇게 말하면 됩니다.

사용 가능한 MCP 도구로 Next.js App Router의 최신 문서를 조회해 주세요.

특정 MCP를 지정할 수도 있습니다.

context7로 Next.js App Router의 최신 사용법을 조회한 뒤,
현재 프로젝트를 어떻게 수정해야 하는지 알려 주세요.

Figma MCP라면 이렇게 말할 수 있습니다.

Figma MCP로 이 디자인 시안을 읽고,
페이지 구조를 분석한 다음 프런트엔드 구현 계획을 생성해 주세요.

GitHub MCP라면 이렇게 말할 수 있습니다.

GitHub MCP로 이 리포지토리의 최근 open issue를 확인하고,
우선순위가 가장 높은 문제 3개를 정리해 주세요.
MCP 설정 파일은 어디에 있나요?

Codex의 MCP 설정은 설정 파일에 저장됩니다.

일반적인 위치는 다음입니다.

~/.codex/config.toml

쉽게 말하면 다음과 같습니다.

config.toml = Codex의 설정 파일

그 안에는 다음과 비슷한 설정이 들어갈 수 있습니다.

[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]

뜻은 다음과 같습니다.

context7이라는 MCP server가 있습니다.
시작 명령은 npx -y @upstash/context7-mcp입니다.

설정 파일에 익숙하지 않다면 처음에는 직접 수정하지 마세요.

처음에는 다음 명령을 사용하세요.

codex mcp add
codex mcp list
codex mcp remove
원격 MCP 추가하기

일부 MCP는 로컬 명령으로 시작하지 않고 URL로 연결됩니다.

이런 유형은 보통 원격 MCP 또는 HTTP MCP라고 부릅니다.

다음 항목이 필요할 수 있습니다.

설정 항목 쉽게 말하면
URL 원격 MCP 서비스 주소
Auth 로그인이 필요한지 여부
Token 접근 자격 증명
OAuth 브라우저 권한 부여 로그인

로그인이 필요하다면 다음을 사용합니다.

codex mcp login MCP-이름

더 이상 쓰지 않을 때는 다음을 사용합니다.

codex mcp logout MCP-이름

초보자에게 권장하는 방식:

먼저 복잡한 권한 부여가 필요 없는 문서 계열 MCP를 사용하세요.
나중에 로그인이 필요한 원격 MCP를 시도하세요.
사용하지 않는 MCP 삭제하기

더 이상 쓰지 않는 MCP는 삭제할 수 있습니다.

codex mcp remove 이름

예시는 다음과 같습니다.

codex mcp remove context7

삭제한 뒤 다시 확인합니다.

codex mcp list

목록에 더 이상 표시되지 않는지 확인합니다.
