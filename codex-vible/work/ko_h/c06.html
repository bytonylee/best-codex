Codex IDE Extension

Codex를 코드 편집기에 직접 설치합니다.

Codex App을 따로 열거나 터미널로 계속 전환할 필요가 없습니다. VS Code, Cursor, Windsurf 같은 편집기의 사이드바에서 Codex를 바로 사용할 수 있습니다.

Codex IDE Extension 이해하기

개념 간단히 말하면
IDE VS Code, Cursor, Windsurf처럼 코드를 작성하는 소프트웨어
Codex IDE Extension 편집기 안에 설치된 Codex
사이드바 Codex가 나타나는 위치로, 채팅 패널과 비슷합니다
현재 파일 편집기에서 지금 열어 둔 파일
선택한 코드 마우스로 선택한 코드 구간
컨텍스트 Codex가 참고할 수 있는 파일, 코드, 오류, 작업 설명

간단히 말하면:

Codex IDE = 코딩 소프트웨어 안에서 Codex에게 바로 작업을 부탁하는 것

Codex IDE Extension이 적합한 사람

대상 적합 여부
VS Code를 사용하는 사람 적합합니다
Cursor를 사용하는 사람 적합합니다
Windsurf를 사용하는 사람 적합합니다
코드를 보면서 바로 수정하고 싶은 사람 적합합니다
Codex가 현재 파일만 보게 하고 싶은 사람 적합합니다
편집기를 전혀 다루고 싶지 않은 사람 그다지 적합하지 않습니다
그래픽 기반 작업 관리를 더 선호하는 사람 Codex App이 더 적합합니다
터미널을 더 선호하는 사람 Codex CLI가 더 적합합니다

Codex IDE Extension이 지원하는 편집기

편집기 설명
VS Code 초보자가 많이 쓰는 코드 편집기
VS Code Insiders VS Code의 테스트 버전
Cursor VS Code 기반의 AI 편집기
Windsurf VS Code 확장 생태계와도 호환되는 AI 편집기
JetBrains IDE 예: IntelliJ, PyCharm, WebStorm, Rider

초보자에게 우선 추천하는 것은:

VS Code 또는 Cursor

Codex IDE Extension 설치 방법

단계 작업
1 VS Code / Cursor / Windsurf를 엽니다
2 Extensions 마켓플레이스를 엽니다
3 Codex를 검색합니다
4 OpenAI의 Codex 확장을 설치합니다
5 설치가 끝나면 편집기를 다시 시작합니다
6 사이드바에서 Codex 아이콘을 찾습니다
7 Codex를 클릭하고 계정에 로그인합니다
8 프로젝트 폴더를 열고 사용을 시작합니다

Cursor에서 Codex 아이콘을 찾을 수 없다면 사이드바 아이콘이 접혀 있을 수 있습니다. 왼쪽 또는 오른쪽 활동 표시줄을 먼저 확인하고 Codex를 고정해 보세요.

첫 로그인

설치 후 Codex IDE Extension이 로그인을 요청합니다.

일반적인 로그인 방식은 두 가지입니다:

로그인 방식 적합한 대상 초보자 추천
ChatGPT 계정 로그인 일반 사용자와 초보자 추천합니다
API Key 로그인 개발자, 자동화, 특수한 상황 처음에는 권장하지 않습니다

초보자는 우선 다음을 선택하는 것이 좋습니다:

Sign in with ChatGPT

이는 ChatGPT 계정으로 로그인하는 방식입니다.

API Key 로그인은 API 과금과 환경 변수를 이해하는 개발자에게 더 적합합니다.

Codex IDE Extension을 여는 위치

설치에 성공하면 Codex는 보통 편집기 사이드바에 나타납니다.

일반적인 위치:

편집기 가능한 위치
VS Code 기본적으로 오른쪽 사이드바 또는 왼쪽 활동 표시줄
Cursor 왼쪽이나 오른쪽에 있거나 접혀 있을 수 있습니다
Windsurf 보통 확장 사이드바에 있습니다
JetBrains 플러그인 패널 또는 도구 창 안에 있습니다

찾을 수 없다면 다음을 시도해 보세요:

1. 편집기를 다시 시작합니다
2. Extensions를 열어 Codex가 설치되어 있는지 확인합니다
3. 왼쪽 활동 표시줄에 Codex 아이콘이 있는지 확인합니다
4. 오른쪽 사이드바에 Codex 패널이 있는지 확인합니다
5. 명령 팔레트에서 Codex를 검색합니다

Codex Web

웹 브라우저에서 사용하는 클라우드 기반 Codex입니다.

로컬 컴퓨터를 계속 켜 둘 필요가 없고, 반드시 터미널에서 작업할 필요도 없습니다. GitHub 리포지토리에 연결하면 Codex가 클라우드 환경에서 코드를 읽고, 작업을 실행하고, 파일을 수정해 검토할 수 있는 결과를 만듭니다.

Codex Web 이해하기

개념 간단히 말하면
Codex Web 웹 버전 Codex
Cloud Task 클라우드 작업으로, 반드시 내 컴퓨터에서 실행되지는 않습니다
Repository GitHub에 있는 코드 리포지토리
Branch 코드 브랜치로, 독립적으로 수정하는 버전과 비슷합니다
Pull Request Codex가 수정한 코드를 검토용으로 제출하는 것
Environment Codex가 클라우드에서 프로젝트를 실행하는 데 필요한 환경
Setup Script 클라우드 환경을 시작하기 전에 실행할 설치 명령
Maintenance Script 의존성 업데이트나 데이터 준비 같은 선택적 유지보수 스크립트

한 문장으로 말하면:

Codex Web = Codex가 클라우드에서 GitHub 프로젝트를 처리하도록 하는 것.

Codex Web이 적합한 사람

대상 적합 여부
GitHub 리포지토리가 있는 사람 적합합니다
Codex가 클라우드에서 작업을 처리하게 하고 싶은 사람 적합합니다
Codex가 PR을 만들게 하고 싶은 사람 적합합니다
팀 프로젝트 개발자 적합합니다
로컬 컴퓨터를 계속 점유하고 싶지 않은 사람 적합합니다
GitHub가 전혀 없는 초보자 그다지 적합하지 않습니다
로컬 HTML 연습만 하는 사람 Codex App이 더 적합합니다
Git / GitHub를 모르는 사람 기초를 먼저 배우는 것이 좋습니다

초보자에게는 다음이 좋습니다:

처음에는 Codex App으로 로컬 연습을 합니다.
프로젝트를 GitHub에 올린 뒤 Codex Web을 배웁니다.

Codex Web 진입 위치

Codex Web의 진입점은 다음입니다:

chatgpt.com/codex

연 뒤에는 다음이 필요합니다:

단계 작업
1 ChatGPT 계정에 로그인합니다
2 Codex 페이지로 들어갑니다
3 GitHub 계정을 연결합니다
4 처리할 리포지토리를 선택합니다
5 클라우드 작업을 하나 만듭니다
6 Codex가 클라우드에서 실행될 때까지 기다립니다
7 결과와 diff를 확인합니다
8 만족하면 Pull Request를 만듭니다

Codex Web과 로컬 Codex의 차이

비교 Codex Web Codex App / CLI / IDE
실행 위치 클라우드 로컬 컴퓨터
프로젝트 출처 GitHub 리포지토리 로컬 폴더 또는 Git 리포지토리
컴퓨터를 계속 켜 둬야 하는지 꼭 그렇지는 않습니다 보통 필요합니다
PR 흐름에 적합한지 매우 적합합니다 가능하지만 로컬 작업에 더 가깝습니다
초보자 연습에 적합한지 보통입니다 App이 더 적합합니다
GitHub에 의존하는지 보통 필요합니다 꼭 그렇지는 않습니다
적합한 작업 리포지토리 작업, PR, 팀 협업 로컬 개발, 빠른 수정, 디버깅

간단히 이해하면:

로컬 Codex = 내 컴퓨터에서 작업합니다
Codex Web = 클라우드에서 GitHub 리포지토리 작업을 도와줍니다

Codex Web 첫 사용 흐름

단계 작업 간단히 말하면
1 Codex Web 열기 웹 버전 Codex를 엽니다
2 ChatGPT 로그인 계정을 확인합니다
3 GitHub 연결 Codex에 내 코드 리포지토리 접근 권한을 줍니다
4 리포지토리 선택 처리할 프로젝트를 하나 고릅니다
5 브랜치 선택 수정을 시작할 버전을 선택합니다
6 작업 입력 Codex에게 할 일을 알려 줍니다
7 실행 대기 Codex가 클라우드에서 처리합니다
8 결과 확인 어떤 파일이 바뀌었는지 봅니다
9 diff 검토 추가된 내용과 삭제된 내용을 확인합니다
10 PR 만들기 만족하면 본인 또는 팀의 검토용으로 제출합니다

GitHub를 연결한다는 뜻

GitHub를 연결한다는 것은:

Codex Web에 사용자가 지정한 GitHub 리포지토리 접근 권한을 주는 것입니다.

Codex Web은 작업을 완료하려면 리포지토리 코드를 읽어야 합니다.

예를 들어 Codex Web에 다음 작업을 요청한다고 해 보겠습니다:

홈페이지 버튼을 클릭해도 반응이 없는 문제를 수정해 주세요.

그러면 Codex가 먼저 프로젝트 코드를 읽고 버튼 로직 위치를 판단한 다음, 관련 파일을 수정합니다.

간단히 말하면:

GitHub = 코드를 보관하는 클라우드 드라이브
Codex Web = 이 코드 클라우드 드라이브에 들어가 프로젝트 수정을 도와줍니다

주의:

신뢰하지 않는 계정이나 조직에 함부로 권한을 부여하지 마세요.
처음부터 Codex가 모든 리포지토리에 접근하게 하지 마세요.
몇 개의 리포지토리만 권한을 줄 수 있다면 필요한 리포지토리만 권한을 주세요.

Repository(리포지토리)란 무엇인가

Repository는 줄여서 repo라고 하며, 다음을 뜻합니다:

하나의 완전한 코드 프로젝트입니다.

예:

my-landing-page
ai-tools-site
social-cover-generator
my-react-app

이 항목들은 모두 GitHub의 리포지토리가 될 수 있습니다.

Codex Web은 보통 하나의 리포지토리 단위로 작업을 만듭니다.

간단히 말하면:

리포지토리 = GitHub에 올라가 있는 프로젝트 폴더

Branch(브랜치)란 무엇인가

Branch는 다음을 뜻합니다:

코드의 독립적인 버전입니다.

예:

main = 공식 버전
feature/homepage = 홈페이지 수정 버전
fix/button-bug = 버튼 bug를 수정하는 버전

Codex Web은 보통 공식 브랜치를 직접 수정하지 않습니다. 대신 특정 브랜치를 기준으로 작업한 뒤 확인 가능한 수정 사항을 만듭니다.

간단히 말하면:

main = 원본 초안
새 브랜치 = 하나를 복사해 수정하는 버전
PR = 수정된 버전을 확인해 달라고 제출하는 것

Pull Request란 무엇인가

Pull Request는 줄여서 PR이라고 합니다.

초보자는 다음처럼 이해하면 됩니다:

Codex가 코드를 수정한 뒤 바로 공식 프로젝트에 합치지 않고 먼저 "수정 요청"을 제출합니다.

PR에서 확인할 수 있는 항목은:

어떤 파일이 바뀌었는지
어떤 코드가 추가되었는지
어떤 코드가 삭제되었는지
테스트를 통과했는지
Codex의 요약 설명
merge할 수 있는지

PR의 장점은:

먼저 확인하고, 그다음 merge합니다.

그래서 Codex Web은 실제 프로젝트와 팀 프로젝트에 적합합니다.

Codex Web에서 작업을 만드는 방법

작업을 만들 때는 다음을 명확히 씁니다:

목표: Codex가 무엇을 해야 하는지
범위: 어디만 수정해야 하는지
제한: 어디는 건드리면 안 되는지
검증: 완료 후 어떻게 확인할지

예시:

홈페이지 버튼을 클릭해도 반응이 없는 문제를 수정해 주세요.

요구사항:
1. 먼저 버튼 클릭 로직이 어디에 있는지 분석합니다
2. 버튼과 관련된 파일만 수정합니다
3. 전체 프로젝트를 리팩터링하지 않습니다
4. 기존 기능을 삭제하지 않습니다
5. 수정 후 빌드 또는 테스트 명령을 실행해 검증합니다
6. 완료 후 어떤 파일을 수정했는지 설명합니다

다음처럼 쓰지 않는 것이 좋습니다:

프로젝트를 좀 최적화해 주세요.

너무 모호하면 Codex가 어디서부터 시작해야 할지 모를 수 있습니다.

Codex Web이 프로젝트를 실행하는 방식

Codex Web은 클라우드에 실행 환경을 만듭니다.

보통 다음 과정을 수행합니다:

1. GitHub 리포지토리 코드를 가져옵니다
2. 지정한 브랜치 또는 커밋으로 전환합니다
3. setup script를 실행해 의존성을 설치합니다
4. 작업에 따라 파일을 읽습니다
5. 코드를 수정합니다
6. 테스트 또는 빌드 명령을 실행합니다
7. diff와 요약을 생성합니다

프로젝트에 의존성 설치가 필요하다면 setup script를 올바르게 설정해야 합니다.

예를 들어 프런트엔드 프로젝트에는 다음이 필요할 때가 있습니다:

npm install

또는:

pnpm install

환경이 올바르게 설정되지 않으면 의존성이 부족해 Codex 실행이 실패할 수 있습니다.

Environment(환경)란 무엇인가

Environment는 다음을 뜻합니다:

Codex Web이 클라우드에서 프로젝트를 실행할 때 사용하는 컴퓨터 설정입니다.

Codex가 알아야 하는 항목은:

어떤 언어를 사용할지
의존성을 어떻게 설치할지
프로젝트를 어떻게 시작할지
테스트를 어떻게 실행할지
어떤 환경 변수가 필요한지
특수 도구가 필요한지

예를 들어 프런트엔드 프로젝트에는 다음이 필요할 때가 있습니다:

Node.js
npm / pnpm
package.json
npm run build

Python 프로젝트에는 다음이 필요할 때가 있습니다:

Python
pip
requirements.txt
pytest

간단히 말하면:

Environment = Codex가 클라우드에서 프로젝트를 실행할 때 필요한 도구상자입니다.

Setup Script란 무엇인가

Setup Script는 다음을 뜻합니다:

Codex Web이 매번 클라우드 환경을 준비할 때 먼저 실행하는 설치 명령입니다.

예:

npm install

또는:

pip install -r requirements.txt

역할:

프로젝트에 필요한 의존성을 먼저 설치합니다.

setup script를 잘못 작성하면 Codex가 프로젝트를 실행하지 못할 수 있습니다.

초보자에게는 다음이 좋습니다:

가장 단순한 설치 명령부터 사용합니다.
setup script에 위험한 명령을 쓰지 않습니다.
비밀번호와 API Key를 넣지 않습니다.

Codex Web의 네트워크 접근

Codex Web의 클라우드 환경은 제한 없는 인터넷 연결과 같지 않습니다.

보통:

의존성 설치 단계에서는 네트워크가 허용될 수 있습니다
실제 agent 작업 단계에서는 기본적으로 네트워크가 제한될 수 있습니다

간단히 말하면:

의존성 설치 때는 네트워크를 사용할 수 있지만, 작업 중에는 마음대로 인터넷을 사용할 수 없을 수도 있습니다.

이 보안 조치는 작업 중 외부 네트워크에 임의로 접근하는 것을 막습니다.

작업에 네트워크가 반드시 필요하다면 워크스페이스와 환경 설정에서 허용되는지 확인해야 합니다.

Codex Web 권한에서 주의할 점

Codex Web은 주로 다음 권한을 다룹니다:

권한 주의할 점
GitHub 리포지토리 권한 어떤 리포지토리를 읽을 수 있는지
브랜치 권한 브랜치를 만들 수 있는지
PR 권한 Pull Request를 만들 수 있는지
Cloud 권한 워크스페이스에서 Codex Cloud 사용을 허용하는지
환경 변수 API Key, token, 비밀번호가 유출되지 않게 합니다
외부 네트워크 클라우드 작업의 네트워크 접근이 허용되는지

초보자 안전 권장사항:

필요한 리포지토리만 권한을 부여합니다.
모든 리포지토리에 권한을 주지 않습니다.
.env, API Key, 비밀번호, token을 작업에 쓰지 않습니다.
Codex가 PR을 자동으로 merge하게 하지 않습니다.
먼저 review하고, 그다음 merge합니다.

Codex Web에 적합한 작업

상황 예시
GitHub 리포지토리의 버그 수정 버튼 수정, 빌드 실패 수정, 테스트 실패 수정
작은 기능 만들기 페이지 하나 추가, 폼 하나 추가
문서 작성 README, 사용 설명, 배포 설명
코드 검토 현재 PR 또는 diff 검토
CI 오류 수정 빌드 로그를 바탕으로 문제 수정
여러 작업의 백그라운드 처리 로컬 컴퓨터를 점유하지 않고 Codex를 클라우드에서 실행합니다
팀 협업 PR에서 팀이 검토하게 합니다

특히 적합한 경우:

GitHub 프로젝트
팀 프로젝트
PR 흐름이 필요한 프로젝트
로컬 컴퓨터를 계속 켜 두고 싶지 않은 작업

Codex Web에 적합하지 않은 작업

초보자는 처음부터 Codex Web으로 다음 작업을 하지 않는 것이 좋습니다:

GitHub가 없는 로컬 작은 연습
Git을 전혀 모르는 프로젝트
실제 프로덕션 환경 배포
데이터베이스 마이그레이션
결제 시스템 수정
PR 자동 merge
많은 파일 삭제
민감한 secret 처리

불가능한 작업은 아니지만, 위험이 더 높습니다.

초보자에게는 다음이 좋습니다:

먼저 Codex App으로 로컬 연습을 합니다.
GitHub를 익힌 뒤 Codex Web으로 리포지토리 작업을 처리합니다.

Codex Web과 Codex Cloud는 같은 것인가

다음처럼 이해하면 됩니다:

Codex Web = 웹에서 조작하는 인터페이스
Codex Cloud = 뒤에서 작업을 실행해 주는 클라우드 기능

다시 말하면:

Codex Web에 작업을 입력하면,
Codex Cloud가 클라우드 환경에서 대신 실행합니다.

초보자는 이 두 용어에 너무 얽매이지 않아도 됩니다.

평소에는 다음처럼 이해하면 됩니다:

Codex Web = 웹 진입점
Cloud task = 클라우드 작업

첫 Codex Web 작업 추천

초보자는 처음부터 복잡한 프로젝트를 선택하지 않는 편이 좋습니다.

간단한 GitHub 리포지토리를 선택하는 것이 좋습니다. 예:

간단한 HTML 페이지
작은 React 프로젝트
개인 홈페이지
README 프로젝트
작은 도구 페이지

작업은 다음처럼 작성하면 됩니다:

이 프로젝트의 README가 명확한지 확인해 주세요.

요구사항:
1. 현재 프로젝트 구조를 읽습니다
2. README에 어떤 내용이 부족한지 설명합니다
3. 설치 단계, 시작 명령, 프로젝트 구조 설명을 보완합니다
4. 코드 로직은 수정하지 않습니다
5. 완료 후 PR을 만듭니다

이 작업은 위험이 낮고 Codex Web 흐름에 익숙해지는 데 적합합니다.

자주 묻는 질문

문제 가능한 원인 해결 방법
리포지토리를 찾을 수 없음 GitHub 권한을 부여하지 않았거나 리포지토리 권한을 주지 않음 GitHub 권한 부여를 다시 확인합니다
Codex가 PR을 만들 수 없음 브랜치 또는 PR 권한이 없음 GitHub 권한을 확인합니다
작업 실행 실패 setup script 오류 또는 의존성 설치 실패 환경 설정을 확인합니다
Codex가 프로젝트 시작 방법을 모름 README 또는 package.json이 명확하지 않음 프로젝트 설명을 보완합니다
테스트 실행 실패 프로젝트 자체에 버그가 있거나 의존성이 완전하지 않음 먼저 Codex에게 실패 원인을 분석하게 합니다
한도 소모가 빠름 작업이 크거나, 모델이 강력하거나, 반복 실행됨 작업 범위를 줄이고 먼저 계획을 세우게 합니다
변경 사항이 너무 많음 작업이 너무 모호함 어떤 파일만 수정할지 명확히 제한합니다
결과가 만족스럽지 않음 요구사항이 불명확하거나 환경 실행에 실패함 댓글을 추가해 Codex가 수정하게 합니다

초보자 안전 규칙

1. 처음부터 모든 GitHub 리포지토리에 권한을 부여하지 않습니다.
2. Codex가 PR을 자동으로 merge하게 하지 않습니다.
3. API Key, 비밀번호, token을 작업에 쓰지 않습니다.
4. .env 파일을 리포지토리에 커밋하지 않습니다.
5. 복잡한 작업은 먼저 Codex에게 계획을 세우게 합니다.
6. PR에서는 반드시 diff를 확인합니다.
7. 이해하지 못한 변경 사항은 merge하지 않습니다.
8. 프로덕션 프로젝트를 Codex가 바로 자동 배포하게 하지 않습니다.
9. 먼저 간단한 리포지토리로 연습합니다.
10. 만족한 뒤 merge합니다.
