Skill

Codex용으로 마련한 “고정 작업 방식”입니다.

Codex는 코드를 읽고 수정하며 명령을 실행할 수 있습니다.

README 작성, 코드 Review, 웹페이지 생성, 문서 정리처럼 같은 유형의 작업을 자주 맡긴다면 그 과정을 Skill로 만들 수 있습니다.

Skill이란 무엇인가

개념 간단히 말하면
Skill 고정된 작업 방법
Prompt 현재 작업의 프롬프트
Workflow 작업을 진행하는 절차
Template 고정 템플릿
Instruction Codex에 적용할 장기 규칙
Resource Skill에 함께 들어 있는 참고 자료
Script Skill에 선택적으로 포함하는 자동화 스크립트

예를 들어 Codex가 매번 README를 작성하고, README에 다음 내용을 반드시 포함해야 한다고 가정해 보겠습니다.

프로젝트 소개
설치 단계
시작 명령
파일 구조
자주 묻는 질문

그러면 README Skill을 만들 수 있습니다.

이후에는 규칙을 매번 다시 설명할 필요가 없습니다. 이 Skill만 호출하면 Codex가 해당 절차에 따라 작성합니다.

Skill인가 MCP인가? 무엇을 언제 써야 하나

플러그인, Skill, MCP의 전체 차이는 앞의 “플러그인, Skill, MCP 세 가지의 관계” 요약표를 참고하세요. 여기서는 가장 흔한 고민인 어떤 요구사항에 Skill을 쓰고 어떤 요구사항에 MCP를 써야 하는지만 다룹니다.

기준은 간단합니다. “어떻게 할 것인가”의 문제에는 Skill을 쓰고, “어떤 도구에 연결할 것인가”의 문제에는 MCP를 씁니다.

요구사항 Skill 또는 MCP
README 작성, 문서 출력 형식 고정 Skill
코드 Review, UI Review Skill
랜딩 페이지 생성, 버그 수정 절차 표준화 Skill
최신 개발 문서, 새 버전 API 조회 MCP
데이터베이스 연결 MCP
Figma 디자인 시안 읽기 MCP
GitHub issue / PR 읽기 MCP
Notion, 내부 지식 베이스, 회사 내부 도구 연결 MCP

Skill과 일반 프롬프트는 무엇이 다른가

한 번만 하는 작업은 프롬프트를 직접 작성합니다. 자주 반복하는 작업은 Skill로 만들기에 적합합니다.

비교 기준 일반 프롬프트 Skill
사용 방식 매번 수동으로 입력 고정 기능으로 저장
안정성 요구사항을 빠뜨리기 쉬움 더 안정적
적합한 상황 임시 작업 반복 작업
재사용성 낮음 높음
내용 구조 프롬프트 하나 지침, 템플릿, 자료, 스크립트
적합한 사람 모든 사람 같은 유형의 작업을 자주 반복하는 사람

Skill은 언제 적합한가

상황 Skill로 만들기 적합한가
같은 유형의 작업을 자주 반복함 적합
매번 많은 규칙을 써야 함 적합
Codex의 출력을 더 안정적으로 만들고 싶음 적합
팀의 여러 사람이 같은 절차를 사용해야 함 적합
작은 일회성 작업 반드시 필요하지는 않음
임시로 문구 한 줄 수정 필요 없음
개념 하나만 질문 필요 없음

Skill에는 보통 무엇이 포함되는가

내용 역할
instructions Codex에 작업 방식을 알려줌
resources 참고 자료, 템플릿, 기준 보관
scripts 작업 자동 처리용 선택 스크립트
examples 예시 입력과 예시 출력
checklist 단계 누락을 막는 체크리스트

Skill의 기본 구조

간단한 Skill은 다음처럼 작성합니다.

# Skill 이름

## 적용 상황
이 Skill이 어떤 작업에 적합한지 설명합니다.

## 작업 목표
Codex가 최종적으로 어떤 결과를 전달해야 하는지 설명합니다.

## 작업 흐름
1. 먼저 입력 내용을 분석합니다
2. 그런 다음 작업 유형을 확인합니다
3. 이후 고정된 단계에 따라 처리합니다
4. 마지막으로 결과와 체크리스트를 출력합니다

## 출력 형식
Codex가 마지막에 어떻게 출력해야 하는지 규정합니다.

## 주의사항
무엇을 하면 안 되는지, 어떤 위험을 알려야 하는지 적습니다.

README Skill 예시는 다음과 같습니다.

# README 생성 Skill

## 적용 상황
현재 프로젝트를 기반으로 README 문서를 생성할 때 사용합니다.

## 작업 목표
구조가 명확하고 초보자가 읽기 좋은 README를 출력합니다.

## 작업 흐름
1. 프로젝트 구조를 읽습니다
2. package.json 또는 주요 진입 파일을 확인합니다
3. 프로젝트 유형을 판단합니다
4. 프로젝트 소개를 생성합니다
5. 설치 단계와 시작 명령을 보완합니다
6. 파일 구조를 설명합니다
7. 자주 묻는 질문을 출력합니다

## 출력 형식
Markdown 형식을 사용합니다.

## 주의사항
존재하지 않는 기능을 지어내지 않습니다.
불확실한 부분은 명확히 표시합니다.

1. 기존 Skill 사용

기존 Skill 사용

플러그인의 Skill 영역에서 시스템이 추천하는 Skill 몇 가지를 볼 수 있습니다.

직접 Skill 만들기

Skill을 직접 만들려면 Codex App의 thread에서 다음을 사용합니다.

$skill-creator

Skill 생성 도우미처럼 동작하며, 반복 절차를 Skill로 정리해 줍니다.

작업 단계:

단계 작업
1 Codex App을 엽니다
2 프로젝트를 선택합니다
3 새 thread를 만듭니다
4 $skill-creator를 입력합니다
5 만들고 싶은 Skill을 알려줍니다
6 사용 상황, 규칙, 예시 출력을 제공합니다
7 Codex에 Skill 파일 생성을 맡깁니다
8 생성 결과를 확인합니다
9 이후 새 thread에서 이 Skill을 사용합니다

예시 프롬프트:

$skill-creator

작업 흐름:
1. 먼저 프로젝트 구조를 읽습니다

7. 주요 폴더의 역할을 설명합니다
8. 자주 묻는 질문을 보완합니다
9. 불확실한 부분은 지어내지 않습니다

Codex CLI에서 Skill을 추가하는 방법

Codex CLI에서 Skill을 추가하는 방법은 세 가지입니다.

1. 기존 Skill 사용
2. $skill-creator로 Skill 만들기
3. SKILL.md 파일을 수동으로 만들기
Skill을 추가하는 세 가지 방법
방법 적합한 사람 간단히 말하면 추천 정도
기존 Skill 사용 처음 사용하는 사람 기존 Skill을 바로 호출 추천
$skill-creator로 생성 프롬프트를 Skill로 바꾸고 싶은 사람 Codex에 Skill 정리를 맡김 가장 권장
SKILL.md 수동 생성 파일 구조에 익숙한 사람 Skill 파일을 직접 작성 심화
방법 1: 기존 Skill 사용

프로젝트 디렉터리로 이동한 뒤 Codex CLI를 실행합니다.

cd 프로젝트-디렉터리
codex

Codex CLI가 열리면 다음을 입력할 수 있습니다.

/skills

또는 다음을 바로 입력합니다.

$

Codex가 현재 사용할 수 있는 Skill을 보여 줍니다.

이미 Skill 이름을 알고 있다면 작업에서 직접 이름을 지정할 수 있습니다.

현재 프로젝트를 기반으로 README를 생성하려면 $readme-skill을 사용해 주세요.

또는:

$ui-review-skill 현재 홈페이지의 시각적 문제를 확인하고 수정 제안을 해 주세요.
기존 Skill 사용 방식
사용법 예시 적합한 상황
/skills Skill 목록 열기 사용 가능한 Skill을 모를 때
$ 입력 Skill 빠르게 선택 빠르게 호출할 때
$skill-name $readme-skill Skill 이름을 명확히 알고 있을 때
자연어 설명 README Skill로 프로젝트 설명을 작성해 주세요 정확한 이름을 모를 때
방법 2: $skill-creator로 Skill 만들기

반복 절차를 Skill로 저장하려면 다음을 사용합니다.

$skill-creator

Skill 생성 도우미처럼 동작하며 다음을 묻습니다.

질문 목적
이 Skill은 무엇을 하는가 용도를 명확히 함
언제 트리거되는가 적용 상황을 분명히 함
스크립트를 포함할 것인가 지시형 Skill인지 판단
출력 형식은 무엇인가 결과를 안정적으로 유지
어떤 제한이 있는가 임의 수정, 지어낸 내용, 임의 실행을 피함
$skill-creator 사용 흐름
단계 작업 목적
1 프로젝트 디렉터리로 이동합니다 Skill을 올바른 프로젝트 안에 생성

3 $skill-creator를 입력합니다 Skill 생성 도우미 시작
4 Skill의 용도를 설명합니다 해야 할 일을 알려줌
5 트리거 상황을 추가합니다 사용 시점을 알려줌
6 작업 흐름을 작성합니다 Codex 실행 단계를 고정
7 출력 형식을 작성합니다 결과를 안정적으로 유지
8 생성 결과를 확인합니다 SKILL.md가 합리적인지 확인
9 다시 열거나 계속 사용합니다 Skill 적용 여부를 테스트

방법 3: Skill 파일을 수동으로 만들기

Skill은 폴더이며, 그 안에 반드시 다음 파일이 있어야 합니다.

SKILL.md

가장 간단한 구조는 다음과 같습니다.

.agents
└── skills
    └── readme-skill
        └── SKILL.md

스크립트, 참고 자료, 리소스 파일도 포함할 수 있습니다.

.agents
└── skills
    └── readme-skill
        ├── SKILL.md
        ├── scripts
        ├── references
        └── assets
Skill 파일 구조 설명
파일 / 폴더 필수 여부 역할
SKILL.md 필수 Skill 이름, 설명, 구체적인 지침 작성
scripts/ 선택 실행 가능한 스크립트 보관
references/ 선택 참고 문서, 기준, 설명 보관
assets/ 선택 템플릿, 이미지, 리소스 파일 보관

Skill의 description이 명확하면 Codex가 언제 사용할지 자동으로 판단하기 쉽습니다.

예를 들어:

description: 사용자가 README, 프로젝트 설명, 설치 튜토리얼, 시작 단계를 생성해야 할 때 사용합니다.

이 설명은 명확합니다.

너무 모호하게 쓰지 않는 것이 좋습니다.

description: 글을 써 주세요.

이렇게 쓰면 Codex는 언제 호출해야 하는지 알 수 없습니다.

Skill은 어디에 두는가

위치 적합한 상황 간단히 말하면
프로젝트의 .agents/skills 현재 프로젝트에서만 사용 프로젝트 전용 Skill
사용자 수준 Skill 디렉터리 내 여러 프로젝트에서 사용 개인 공통 Skill
팀 / 관리자 설정 팀원이 통일해서 사용 팀 공유 Skill
플러그인 안 다른 사람이 설치하도록 패키징해 배포 공식 기능 패키지
