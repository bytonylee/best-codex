MCP

Only users doing advanced AI programming need this; most people can skip it.

MCP is an interface that lets Codex connect to external tools.

Codex can already read code, edit code, and run commands.

MCP connects Codex to additional external tools, data sources, or services.

What is MCP?

Concept In simple terms
MCP A standard interface for connecting external tools
MCP Server A service that provides tool functions
Tool A specific function that Codex can call
Config The MCP configuration file
STDIO Server An MCP service started through a local command
HTTP Server An MCP service connected through a URL
Context Context information that external tools provide to Codex

A simple analogy:

Codex = A person who can do work
MCP = Sockets that connect them to different tools
MCP Server = A toolbox plugged into the socket
Tool = A specific tool inside the toolbox

For example, a document MCP can let Codex read documents.

A database MCP can let Codex query a database.

A design-tool MCP can let Codex read design-file information.

What is MCP useful for?

Scenario How to use MCP
Looking up development documentation Connect a documentation MCP so Codex can look up APIs for newer versions
Connecting a database Let Codex query the database schema or test data
Connecting design tools Let Codex read design files and component information
Connecting project management tools Read issues, tasks, and requirement descriptions
Connecting internal systems Call internal company tools or data sources
Connecting a knowledge base Let Codex work from team documentation
Connecting automation tools Let Codex call additional scripts or services

For beginners, the rule is:

For ordinary coding, you do not necessarily need MCP.
Consider MCP only when Codex needs to access external tools or external data.

What is an MCP Server?

Think of an MCP Server as this:

A service that provides tool functions to Codex.

Examples:

MCP Server type What it can provide
Documentation MCP Look up development and API documentation
Database MCP Read table schemas and test data
GitHub MCP Read issues, PRs, and repository information
Figma MCP Read design file information
Notion MCP Read knowledge base pages
Browser MCP Visit web pages and read page information
Internal tool MCP Connect to the company's own systems

In simple terms:

MCP Server = An external tool service that Codex can call.

How to use MCP in Codex CLI

Using MCP in Codex CLI means this:

You connect external tools to the terminal version of Codex.

Examples:

Documentation MCP: lets Codex query development documentation
GitHub MCP: lets Codex read issues, PRs, and repository information
Figma MCP: lets Codex read design files
Database MCP: lets Codex query database schemas

Beginners can understand it this way:

Codex CLI = An AI programming assistant in the terminal
MCP = An interface for connecting external tools to Codex CLI
Basic flow in the CLI
Step Action In simple terms
1 Open a terminal PowerShell / Terminal
2 Go to the project directory Let Codex see the current project
3 Add an MCP server Connect external tools to Codex
4 Check whether the MCP was added Confirm that the tool is available
5 Start Codex CLI Open the Codex conversation screen
6 Run /mcp to view tools See which MCPs are available
7 Use MCP in the task Let Codex use external tools
8 Review results and permission prompts Check whether the action is safe
Common MCP terminal commands
Command Purpose In simple terms
codex mcp --help Show MCP command help Check this first when you do not know how to use it
codex mcp list Show configured MCP servers See which external tools are connected
codex mcp add Add an MCP server Add an external tool to Codex
codex mcp remove Delete an MCP server Remove it when you no longer need it
codex mcp get Show details for a specific MCP server See its configuration
codex mcp login Log in to an MCP that requires authorization Authorize some remote MCPs
codex mcp logout Log out of an MCP authorization Clear the connection state
/mcp Show MCPs in a Codex session See which tools this session can call
Basic format for adding an MCP

The basic command to add an MCP is usually:

codex mcp add name -- start-command

In simple terms:

name = the name you give this MCP
startup-command = how this MCP starts

Example:

codex mcp add context7 -- npx -y @upstash/context7-mcp

This command means:

Add an MCP called context7 to Codex.
It starts the @upstash/context7-mcp tool through npx.
Viewing MCPs already added

After adding one, you can run:

codex mcp list

Purpose:

View which MCP servers are currently configured in Codex CLI.

If the name you just added appears, the configuration was saved.

Viewing MCP after starting Codex

First go to the project directory:

cd project-directory

Then start Codex:

codex

After Codex CLI starts, type:

/mcp

Purpose:

View the MCP tools available in the current session.

If the MCP does not appear, check these possible causes:

Problem Possible reason
It was not added The codex mcp add command failed
MCP failed to start Dependencies are not installed or the command is wrong
The name is wrong The server name was typed incorrectly when calling it
Authorization is required You have not logged in to the external service yet
The configuration was not refreshed You need to restart Codex CLI
Calling MCP from a task

After MCP is configured, you do not need to remember complex commands.

In Codex CLI, you can say:

Please use the available MCP tools to query the latest documentation for Next.js App Router.

You can also specify a particular MCP:

Please use context7 to query the latest usage of Next.js App Router,
and then tell me how the current project should be modified.

For a Figma MCP, you can say:

Please use Figma MCP to read this design file,
analyze the page structure, and generate a frontend implementation plan for me.

For a GitHub MCP, you can say:

Please use GitHub MCP to view recent open issues in this repository,
and help me organize the top 3 highest-priority problems.
Where is the MCP configuration file?

Codex writes MCP configuration to a configuration file.

The common location is:

~/.codex/config.toml

In simple terms:

config.toml = Codex's configuration file

It may contain settings like this:

[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]

This means:

There is an MCP server called context7.
The startup command is npx -y @upstash/context7-mcp.

If you are not familiar with configuration files, do not edit them manually at first.

Use these commands instead:

codex mcp add
codex mcp list
codex mcp remove
Adding a remote MCP

Some MCPs do not start from local commands. They connect through URLs.

These are usually called remote MCPs or HTTP MCPs.

They may need:

Configuration item In simple terms
URL Remote MCP service address
Auth Whether login is required
Token Access credential
OAuth Browser-based authorization

If login is required, use:

codex mcp login MCP-name

When you no longer need it, use:

codex mcp logout MCP-name

For beginners:

Start with documentation-type MCPs that do not require complex authorization.
Try remote MCPs that require login later.
Deleting unused MCPs

If you no longer use an MCP, delete it:

codex mcp remove name

Examples:

codex mcp remove context7

Check again after deleting it:

codex mcp list

Confirm that it no longer appears in the list.
