Codex Web

A cloud-based Codex interface used in a web browser.

You do not need to keep your local computer on, and you do not have to work in the terminal. Codex Web can connect to a GitHub repository, let Codex read code, run tasks, modify files in a cloud environment, and produce results for review.

Concept In simple terms
Codex Web The web version of Codex
Cloud Task A cloud task that does not have to run on your computer
Repository A code repository on GitHub
Branch A code branch, like an independent version for changes
Pull Request Submit the code Codex changed so you can review it
Environment The environment Codex needs to run the project in the cloud
Setup Script An installation command that runs before the cloud environment starts
Maintenance Script An optional maintenance script, such as one for updating dependencies or preparing data

In one sentence:

Codex Web = Let Codex handle GitHub projects for you in the cloud.

What connecting GitHub means

Connecting GitHub means:

It gives Codex Web permission to access the GitHub repositories you specify.

Codex Web needs to read the repository code before it can complete tasks.

For example, if you ask Codex Web to do this:

Please help me fix the issue where the homepage button does nothing when clicked.

Codex first reads your project code, determines where the button logic is, and then modifies the relevant files.

In short:

GitHub = A cloud drive for code
Codex Web = Enters that code cloud drive to help you modify the project

Note:

Do not casually authorize accounts or organizations you do not trust.
Do not give Codex access to all repositories right away.
If you can authorize only a few repositories, authorize only the ones needed.

What a Repository is

Repository, often shortened to repo, means:

A complete code project.

For example:

my-landing-page
ai-tools-site
social-cover-generator
my-react-app

These can all be repositories on GitHub.

Codex Web usually creates tasks for one repository.

In short:

Repository = A project folder stored on GitHub

What a Branch is

Branch means:

An independent version of the code.

For example:

main = Official version
feature/homepage = Homepage change version
fix/button-bug = Version that fixes the button bug

Codex Web usually does not modify the official branch directly. Instead, it works from a branch and produces changes you can inspect.

In short:

main = Original draft
New branch = Copy one version out for editing
PR = Submit the changed version for you to inspect

What a Pull Request is

Pull Request is often shortened to PR.

Beginners can understand it as:

After Codex changes the code, it does not merge the code directly into the official project. Instead, it first submits a "change request."

In a PR, you can see:

Which files changed
Which code was added
Which code was deleted
Whether tests passed
Codex's summary
Whether it can be merged

The main benefit of a PR is:

Check first, then merge.

This makes Codex Web well suited to real projects and team projects.

How to create a task in Codex Web

When you create a task, state these clearly:

Goal: What you want Codex to do
Scope: Which areas it should change only
Limits: Which areas it must not touch
Verification: How to check the result after completion

Example:

Please fix the issue where the homepage button does nothing when clicked.

Requirements:
1. First analyze where the button click logic is
2. Modify only files related to the button
3. Do not refactor the whole project
4. Do not delete existing features
5. After fixing, run the build or test command to verify
6. After completion, explain which files were changed

Do not write:

Help me optimize the project.

This is too vague. Codex may not know where to start.

How Codex Web runs projects

Codex Web creates a runtime environment in the cloud.

It usually does the following:

1. Pulls the GitHub repository code
2. Switches to the specified branch or commit
3. Runs the setup script to install dependencies
4. Reads files according to your task
5. Modifies code
6. Runs tests or build commands
7. Generates a diff and summary

If the project needs dependencies, configure the setup script properly.

For example, a frontend project may need:

npm install

Or:

pnpm install

If the environment is not configured correctly, Codex may fail because dependencies are missing.

What an Environment is

Environment means:

The computer configuration Codex Web uses to run the project in the cloud.

Codex needs to know:

Which language to use
How to install dependencies
How to start the project
How to run tests
Which environment variables are needed
Whether special tools are needed

For example, a frontend project may need:

Node.js
npm / pnpm
package.json
npm run build

A Python project may need:

Python
pip
requirements.txt
pytest

In short:

Environment = The toolbox Codex needs when running a project in the cloud.

What a Setup Script is

Setup Script means:

A set of installation commands that Codex Web runs first each time it prepares the cloud environment.

For example:

npm install

Or:

pip install -r requirements.txt

Its purpose:

Install the dependencies the project needs first.

If the setup script is wrong, Codex may not be able to run the project.

For beginners:

Start with the simplest installation command.
Do not write dangerous commands in the setup script.
Do not put passwords or API Keys in it.

Network access in Codex Web

The cloud environment in Codex Web does not always have unrestricted internet access.

Usually:

Network access may be allowed during dependency installation
Network access may be restricted by default during the actual agent task

In short:

Dependency installation can use the network, but the work phase may not have unrestricted network access.

This security measure prevents arbitrary access to external networks during tasks.

If your task must use the network, check whether the workspace and environment settings allow it.

Are Codex Web and Codex Cloud the same thing?

Use these meanings:

Codex Web = The interface you operate in the browser
Codex Cloud = The cloud capability that runs tasks behind the scenes

In other words:

You enter a task in Codex Web,
and Codex Cloud executes it for you in a cloud environment.

Beginners do not need to worry much about these two terms.

For everyday use, think of them this way:

Codex Web = Web entry point
Cloud task = Cloud task

Recommended first Codex Web task

Beginners should avoid choosing a complex project for the first time.

Choose a simple GitHub repository, such as:

A simple HTML page
A small React project
A personal homepage
A README project
A small tool page

You can write the task like this:

Please help me check whether this project's README is clear.

Requirements:
1. Read the current project structure
2. Explain what the README is missing
3. Add installation steps, startup commands, and a project structure description
4. Do not modify code logic
5. Create a PR after completion

This task is low risk and helps you learn the Codex Web workflow.

FAQ

Question Possible cause Solution
Cannot find the repository GitHub is not authorized, or repository permission was not granted Check GitHub authorization again
Codex cannot create a PR No branch or PR permission Check GitHub permissions
Task run failed Setup script error or dependency installation failure Check environment configuration
Codex does not know how to start the project README or package.json is unclear Add project instructions
Tests fail The project itself has bugs or incomplete dependencies Ask Codex to analyze the cause of failure first
Quota is consumed quickly The task is large, the model is powerful, or it runs repeatedly Narrow the task scope and ask it to plan first
Too many changes The task is too vague Clearly limit which files may be changed
The result is unsatisfactory The requirement is unclear or the environment failed Add a comment and ask Codex to revise

Beginner safety rules

1. Do not authorize all GitHub repositories right away.
2. Do not let Codex merge PRs automatically.
3. Do not put API Keys, passwords, or tokens into tasks.
4. Do not commit .env files to the repository.
5. Ask Codex for a plan first for complex tasks.
6. Always review the diff in the PR.
7. Do not merge changes you do not understand.
8. Do not let Codex automatically deploy production projects directly.
9. Practice with a simple repository first.
10. Merge only after you are satisfied.
