How the CLI works

Codex CLI follows this general flow:

Read the project
→ Understand the task
→ Propose a plan
→ Modify files
→ Run commands
→ Wait for approval
→ Show the diff
→ Handle failures

Beginners do not need to understand every technical detail at first. Just know this:

Codex CLI does more than chat. It works in the current project directory: it reads files, edits files, runs commands, and shows the results for review.

How Codex reads a project

When you run this in a project directory:

codex

Codex treats the current directory as the workspace.

For example, if you start it in this directory:

D:\AI-Codex-Projects\hello-codex

Codex works with the contents of that folder.

It may read:

Content Purpose
Project files Understand the current code
Folder structure Identify whether the project is a frontend, backend, or script project
package.json Identify startup commands, dependencies, and project type
README.md Understand the project description
AGENTS.md Read the working rules you defined for Codex
Error logs Analyze the cause of problems
Git status Identify which files have changed

Rule:

Whichever folder you start Codex in,
Codex treats that folder as the current project by default.

Do not start it carelessly in places like these:

C:\
Desktop
Downloads folder
System directory
Important data folder

Recommended practice:

cd project-directory
codex
How Codex understands a task

When you enter a task, Codex first works out what you want it to do.

For example, if you enter:

Please help me make a simple web page with a black background and Hello Codex displayed in the center.

Codex identifies:

What it understands Example
Task type Create a new web page
Modification scope Current project files
Files that may be needed index.html, style.css
Whether commands are needed Simple HTML may not require this
Risk level Relatively low risk

If you enter:

Please check why npm run build is failing.

Codex identifies:

What it understands Example
Task type Troubleshoot a build failure
Commands that may be needed npm run build
Files that may need to be read package.json and files related to the error
Whether code changes are needed Possibly
Whether approval is needed Depends on the permission settings

Beginner tip:

Clear tasks produce more stable Codex results.

Recommended wording:

Please help me complete [specific task].

Requirements:
1.
2.
3.

Constraints:
1. Do not modify unrelated files
2. Do not delete existing features
3. After finishing, tell me which files were changed
How Codex proposes a plan

For a complex task, Codex usually analyzes the problem before proposing a plan.

You can also ask it to plan first:

Please give me a plan first. Do not modify files directly.

Or use:

/plan

A plan usually includes:

Content Purpose
Which files it will inspect Avoid scanning the project blindly
How it will modify them Show the direction before editing
Which commands it may run Review risks in advance
Which areas it expects to affect Help you decide whether to accept the plan

For example:

Plan:
1. First inspect package.json to confirm the startup command
2. Run npm run build to reproduce the error
3. Locate related files based on the error
4. Fix the problem with the smallest possible change
5. Run build again to verify

Beginner advice:

For simple tasks, you can let it work directly.
For complex tasks, ask it to /plan first.

Planning first is especially recommended for these tasks:

Fixing complex bugs
Modifying multiple files
Refactoring a project
Adding features
Build failures
Dependency upgrades
How Codex modifies files

After Codex decides that files need changes, it edits them in the current project.

It may:

Operation Example
Create a new file Create index.html
Modify a file Modify style.css
Delete code Delete unused code
Rename a file Adjust a file name
Split files Split code into multiple modules

Beginners should note:

Codex may make the right changes, but it may also change too much.

Build this habit:

After it finishes making changes, do not trust them immediately.
Always review the diff.

You can add constraints in advance:

Please modify only index.html and style.css. Do not modify other files.

Or:

Please fix the problem with the smallest possible change. Do not refactor the entire project.

This can reduce overly broad Codex changes.

How Codex runs commands

Codex can modify files and run terminal commands.

Common commands include:

Command Purpose
npm install Install dependencies
npm run dev Start the development project
npm run build Check whether the project can build
npm test Run tests
git status View Git status
git diff View code changes

For example, if you ask it to fix a build failure, it may run:

npm run build

It then continues editing based on the error.

Beginners do not need to avoid commands, but they should understand them before allowing them.

If you do not understand, you can ask it to explain first:

Please first explain the commands you plan to run and what each command does. Do not execute them directly.

Be especially cautious when you see these commands:

rm -rf
sudo
curl xxx | sh
git reset --hard
git clean -fd

These commands may delete files, modify the system, reset code, or execute remote scripts.

How Codex waits for user approval

Codex CLI includes permission controls. Not every operation runs directly.

When Codex needs to perform a sensitive operation, it may stop and ask you.

For example:

Operation Why approval may be needed
Install dependencies from the internet May download external code
Access files outside the project Goes beyond the current workspace
Modify external files May affect other projects
Run high-risk commands May delete or overwrite content
Use higher privileges Creates greater risk

Approval meaning:

Approve = you allow Codex to continue with this step.
Reject = do not perform this step.

If you do not understand what it wants to do, do not click Allow immediately.

You can ask first:

Please explain what this operation does, its risks, and whether there is a safer alternative.

Recommended permissions for beginners:

Keep approval requests enabled.
Do not casually enable full access.
How Codex shows a diff

A diff is a comparison of the code before and after Codex changes it.

You can enter this in Codex CLI:

/diff

Codex shows the current changes.

Color meaning:

Green = added content
Red = deleted content

Use the diff to confirm:

Checkpoint What to look for
Whether the correct files were changed Whether unrelated files were changed
Whether important code was deleted Pay close attention to red deleted sections
Whether complex dependencies were added Whether unnecessary packages were installed
Whether the change is too large A small task should not become a major refactor
Whether it meets the requirement Whether it implements the effect you requested

Recommended flow:

Codex finishes changes
→ Enter /diff
→ Review changes
→ If unsatisfied, ask it to keep modifying or revert
→ If satisfied, then git commit

Do not look only at Codex's summary.

Check:

What it actually changed.
How Codex handles failures

Codex can fail while executing a task.

Common failures include:

Failure type Example
Command failure npm run build reports an error
Missing dependency A package is not installed
Code error Blank page or function error
Insufficient permissions No internet or file access permission
Misunderstood requirement It changed something you did not want
Modification scope too large It changed unrelated files along the way

Codex usually continues analyzing based on the failure result.

For example:

Running npm run build fails
→ Read the error message
→ Locate related files
→ Modify code
→ Run build again

Note:

Do not let it keep retrying without a reason.

If it fails repeatedly, pause it and ask it to analyze again:

Stop for a moment. Please summarize the current cause of failure and do not continue modifying files.

Or:

Please list the methods you have already tried, why they failed, and the smallest-change plan for the next step.

If the changes became messy, you can say:

Please revert the changes you just made and restore the state before the modifications.

Or check it yourself with Git:

git status
git diff

Then decide whether to keep them.

Recommended beginner workflow
Step Action Purpose
1 cd project-directory Enter the correct project
2 Codex Start Codex CLI
3 Enter the task Tell Codex what to do
4 Use /plan first for complex tasks Review the approach first
5 Wait for Codex to read the project Let it understand the context
6 Approve sensitive operations Understand them before allowing them
7 Wait for it to modify files Execute the task
8 Run commands to check Verify the result
9 /diff View changes
10 Continue modifying if unsatisfied Iterate and improve
11 git commit after you are satisfied Save the version
One-sentence summary

The way Codex CLI works is not "ask one question, get one answer"; it is a complete programming flow:

Read the project
→ Think through a plan
→ Modify files
→ Run commands
→ Wait for approval
→ Review the diff
→ Fix failures
→ Deliver the result

Common CLI issues

Most common Codex CLI issues come from one of these areas, not from Codex itself being broken:

Most common beginner issues
Issue Common cause Solution
Entering codex has no response Codex is not installed properly, or the command was not added to environment variables Run codex --version first to check
Shows command not found The terminal cannot find the Codex command Reinstall Codex CLI or reopen the terminal
You do not know where to run Codex You have not entered the project directory cd into the project directory first, then run Codex
Codex reads the wrong project It was started in the wrong folder Exit, enter the correct project directory, and restart
Login fails The browser did not open, the network has a problem, or the account is not logged in Use codex login to log in again
API Key login fails The key is not set, the key is wrong, or the environment variable has not taken effect Set the environment variable again, then log in
Codex keeps waiting It may be waiting for you to approve permissions Check whether the terminal has an approval prompt
Codex cannot access the internet Sandbox or permission restrictions Manually approve when internet access is needed
After changes, you do not know what changed You did not review the diff Enter /diff in Codex
What if it breaks things? You did not save with Git in advance Use git diff to check, and revert if needed
Installation issues
Issue Cause Solution
codex --version has no output Codex was not installed successfully Reinstall Codex CLI
codex: command not found The command was not added to PATH Reopen the terminal or reinstall
npm installation fails Node.js / npm is not installed properly Run node -v and npm -v first
Cannot find the command after installing on Windows PowerShell has not refreshed environment variables Close the terminal and open it again
The version is outdated Codex CLI has not been updated Run codex update or reinstall

Troubleshooting commands:

codex --version
node -v
npm -v
codex doctor

Beginner advice:

After installation, the first thing to do is not to use it directly, but to run codex --version first.
If you can see a version number, the basic installation is normal.

For local learning, prefer logging in with a ChatGPT account.

Permission and sandbox issues
Issue Cause Solution
Codex says approval is required It wants to execute a sensitive operation Allow it only after you understand it
Codex cannot access the network The sandbox restricts internet access by default Manually approve when needed
Codex cannot read files outside the project It is outside the workspace scope Do not loosen this restriction casually
Codex cannot modify some files Insufficient permissions or read-only mode Check /permissions
Codex requests full access The task requires broader permissions Beginners should not approve this casually

Recommended settings:

sandbox: workspace-write
approval: on-request

Setting meanings:

workspace-write = allow work inside the current project
on-request = ask you first for sensitive operations

Do not casually use:

danger-full-access
--yolo
--dangerously-bypass-approvals-and-sandbox

When you see a permission request you do not understand, you can ask:

Please explain why this operation needs permission, which files it will affect, and whether there is a safer alternative.
Command-running issues
Issue Cause Solution
npm run dev fails Dependencies are not installed or the script does not exist Look at package.json first
npm install fails Network, registry, permission, or dependency conflict Ask Codex to analyze the error first
npm run build fails The project code itself has errors Ask Codex to reproduce it and make the smallest fix
A command is stuck The development server keeps running Use /ps to view background tasks
Want to stop a command The command keeps occupying the terminal Use /stop to stop the background task

Command Meaning

Diff and change issues
Issue Cause Solution
You do not know what Codex changed You did not review the diff Enter /diff
The diff contains too many changes Codex's modification scope is too large Ask it for the smallest possible change
Unrelated files were changed The task constraints were not clear Ask it to revert unrelated changes
Important code was deleted You did not check the red deleted sections Restore with Git or ask it to revert
/diff shows nothing There are no file changes, or the changes have already been saved/handled Check again with git status

Recommended review flow:

Codex completes the task
→ Enter /diff
→ See which files changed
→ Check the red deleted sections
→ Check whether unrelated files were changed
→ If satisfied, then git commit

You can write the prompt like this:

Please modify only files related to the current task.
Do not refactor the entire project.
After finishing, list which files were modified.
Git-related issues
Issue Cause Solution
Do not know how to recover after breaking things You did not save a version with Git Use git init and commit first next time
git status shows many files Codex or you changed many things Use git diff to inspect them one by one
Do not know which changes to keep You did not review the diff Do not commit yet
Want to roll back after commit You are not familiar with Git basics Ask Codex to explain rollback options first
Codex changed files it should not have changed The task scope was too broad Ask it to revert unrelated files

For a beginner's first project, run this first:

git init
git add .
git commit -m "initial commit"

After each Codex change, run:

git status
git diff

Git command meanings:

git status = see which files changed
git diff = see exactly what changed
commit = save a version
Model and quota issues
Issue Cause Solution
A certain model is not visible Plan, region, or permissions differ Use one of the currently available models
Tasks become slow Strong model, high reasoning, or large project Lower reasoning or narrow the task scope
Quota is consumed too quickly High reasoning, many rounds of edits, or reading a large project Use low/medium reasoning for small tasks
A limit message appears Your current plan's quota has been used up Wait for quota to recover or buy extra quota
API Key incurs costs API login is billed by API usage Beginners should prefer ChatGPT login

Quota-saving advice:

Do not use the highest reasoning for small tasks.
Do not ask Codex to scan the entire project at once.
Do not repeatedly ask it to refactor broadly.
Specify files when you can.
For complex tasks, use /plan first, then modify.

Recommended configuration:

Normal tasks: default model + medium reasoning
Complex bugs: high reasoning
Small changes: low reasoning
Codex gets stuck or the result is wrong
Issue Cause Solution
Codex stays idle for a long time It is waiting for permissions, a command is stuck, or the task is too large Check whether there is an approval prompt or /ps
Codex repeatedly fails to fix it It has not found the root cause Ask it to summarize the failure cause first
Codex makes things messier with each change The modification scope was not limited Pause it and request the smallest possible change
Codex misunderstands the requirement The task description is too vague Rewrite the goal, requirements, and constraints clearly
The output is too long and messy The conversation context is too long Use /compact

You can stop it like this:

Stop for a moment. Do not continue modifying files.
Please summarize what has been done so far, where it failed, and what the smallest next change should be.

If it went in the wrong direction, you can say:

This direction is wrong. Please revert the unrelated changes you just made and keep only the changes related to the homepage style.
