Part 2: Install, configure, and set up your environment

Before you install

Account preparation

Individual users should prepare the following:

  • A ChatGPT account
  • Use a network connection that can reach ChatGPT / OpenAI services normally.
  • Choose a current ChatGPT plan that includes Codex. Plan names, quotas, and feature coverage may change, so check the official page and the details shown in your account.

System setup

Codex is available in four main forms:

Codex App desktop version Beginners and users who want a graphical interface Windows or macOS
Codex CLI People familiar with the terminal Terminal, Git, project environment
Codex IDE Extension plugin People who use VS Code / Cursor / Windsurf Editor + plugin
Codex Web / Cloud People who want Codex to work remotely on GitHub projects GitHub repository

Project directory setup

Codex works inside a specific project directory rather than only in chat. In the official getting-started flow, you log in to Codex, choose a folder on your computer or a Git repository, and then start your first task.

Create a dedicated practice directory in advance, for example:

D:\AI-Codex-Projects

You can put projects like these inside:

hello-web
ai-tools-page
product-cover-tool
landing-page-demo

Do not start by letting Codex operate on your most important real project. Use practice projects first to learn how it edits files, runs commands, and generates results.

Permissions and security setup

Codex can read and modify files, and it can also run commands in your project directory. The CLI documentation says it can read and modify code in the directory you choose, and run commands.

Before installing, pay attention to the following:

Point Recommendation
Do not put important files there directly Use a test project first
Do not write passwords/API Keys in code Use a .env file and avoid uploading it
Make a Git commit before starting Makes it easier to roll back
Read the commands Codex wants to execute carefully If you do not understand a command, ask it to explain first
Do not give it access to the entire C drive Select only the specific project folder

Initialize Git for each project first:

git init
git add .
git commit -m "initial commit"

Then if Codex breaks something, you can roll back.

Codex App installation and getting started (recommended for beginners and the most capable option)

Download and install

macOS installation

If you use a Mac, first confirm your chip type.

Click the Apple icon in the upper-left corner of your computer and choose "About This Mac".

If it shows:

  • For an Apple M1, M2, M3, or M4 device, choose the Apple Silicon version.
  • Intel: choose the Intel version

On the official Codex App page, download the version that matches your chip. When the download finishes, open the installer package and drag Codex into the "Applications" folder.

After installation, open Codex from "Applications".

The first time you open it, the system may prompt:

"This is an app downloaded from the Internet. Are you sure you want to open it?"

Choose "Open".

Difference between Intel Mac and Apple Silicon

Macs mainly use two kinds of chips:

Type Common models Version to download
Apple Silicon M1 / M2 / M3 / M4 Mac Apple Silicon version
Intel Mac Older Macs with Intel chips Intel version

The quickest way to check:

Open "About This Mac" and look at the chip information.

If it shows an Apple M series chip, it is Apple Silicon.

If it shows Intel Core i5, Intel Core i7, or Intel Core i9, it is an Intel Mac.

Choose the version carefully. The wrong version may fail to install, fail to open, or run unstably.

Windows installation

If you use Windows, go to the official Codex App page and choose the Windows version.

The Windows version usually redirects to Microsoft Store for installation.

Installation steps:

  1. Open the official Codex App page
  2. Click the Windows download entry

  1. Microsoft Store opens

  1. Click "Get" or "Install" (I have already installed it here, so it shows Open)
  2. Open Codex App
  3. Codex App is now installed

Opening Codex App for the first time

Choose a project directory

After you open Codex App for the first time and log in, Codex asks you to choose a project directory.

A "project directory" means:

The folder where Codex will work.

For example, if you want Codex to help you build a web page, create a new folder in advance:

hello-codex

Then choose this folder in Codex App.

For your first run, choose a clean practice directory. Do not choose the C drive directly, and do not start with an important work project.

Recommended directory structure:

AI-Codex-Projects
└── hello-codex
    └── index.html

After you choose a project directory, Codex knows which files to read and modify, and where to run commands.

Understanding the project list

After entering Codex App, you will usually see the project list on the left.

The project list means:

The different code folders you have given to Codex.

For example:

hello-codex
ai-first-page

Each project corresponds to a local folder on your computer, or to a Git repository.

If you previously opened projects in Codex App, Codex CLI, or Codex IDE Extension, those projects may also appear in the list.

Remember this:

The project list is not a chat history list; it is a "code project list".

When you click into different projects, the set of files Codex can see is different.

Understanding threads (conversations)

A thread means:

A task conversation inside the same project.

For example, in the hello-Codex project, you can open multiple threads:

Thread 1: build a homepage
Thread 2: fix the issue where clicking the button does nothing
Thread 3: optimize mobile styles
Thread 4: help me write the README

Each thread has its own context.

When you ask Codex in Thread 1 to build a homepage, it keeps working around that task.

When you ask it in Thread 2 to fix a bug, it works around a different task.

A simple way to think about it:

  • Project = a company
  • thread = an employee in the company

Do not put every task into the same thread.

Better:

Open one thread for each clear task.

For example:

Please help me build a personal homepage

This is one thread.

Please check why the mobile layout is misaligned

This is another thread.

This keeps the project organized and helps Codex understand task boundaries.

Understanding the task window

The task window is where you talk to Codex and assign work.

Enter a task here, for example:

Please help me build a simple web page with a black background and Hello, Codex displayed in the center.

You can also ask follow-up questions:

Please make this page look more like a technology product homepage.

The task window usually shows these items:

Content Purpose
Your task description Tells Codex what to do
Codex's plan How it plans to do it
Codex's execution process Shows Codex reading files, editing files, and running commands
Codex's summary What Codex changed at the end
Follow-up input box Use this to ask for more changes

The first time you use it, avoid overly complex tasks.

Not recommended:

Help me build a complete AI tools platform with login, payment, database, and admin dashboard.

Recommended:

Please help me build a simple product introduction page using only HTML and CSS.

The clearer the task, the easier it is for Codex to do it well.

Understanding the review pane

The review pane is:

The place where you check what Codex changed.

After Codex finishes editing files, do not read only its text summary. Open the review pane and inspect the actual changes.

It shows:

  • Which files were modified
  • Where code was added
  • Where code was deleted
  • Which changes can be accepted
  • Which changes can be reverted

For beginners, the review pane is:

Codex's "homework inspection area".

Do not simply trust Codex after it finishes writing. Check here to see exactly what it submitted.

If you are not satisfied with a line of code, leave a comment there and ask Codex to revise it.

For example, you can write:

The button color here is too bright. Change it to a more restrained dark blue.

Or:

This code is too complex. Please rewrite it in a way that is easier for beginners to understand.
Understanding diff

A diff compares code changes.

For beginners:

Green = added content
Red = deleted content

For example, if Codex originally did not write a title and later adds a line:

<h1>Hello, Codex</h1>

This line appears as an addition.

If Codex deletes old code, that part appears as deleted.

The diff shows:

Exactly what Codex changed.

Do not look only at the final page or read only Codex's summary.

Always check the diff.

Codex may sometimes:

  • Change places you did not ask it to change
  • Delete code that you still need
  • Make simple code complex
  • Modify multiple files without explaining clearly

Build this habit from the first use:

Every time Codex completes a task, look at the diff first, then decide whether to accept it.
Recommended workflow after opening it for the first time

When you open Codex App for the first time, follow this order:

1. Log in to ChatGPT
2. Choose a practice project directory
3. Create or choose a thread
4. Enter a simple task in the task window
5. Wait for Codex to modify files
6. Open the review pane
7. View the diff
8. After confirming there are no issues, continue making changes

Recommended first task:

Please help me build a simple web page with these requirements:
1. Black background
2. Large text Hello, Codex displayed in the center of the page
3. White font
4. The whole page is centered horizontally and vertically
5. Use only HTML and CSS

This task is simple enough for learning the basic Codex App workflow.

Create a project

You can create a new project directly in Codex, or use an existing project.

The project you create or choose appears in the project column, which makes it easier to manage later.

thread

A thread is a "separate task conversation" inside a project.

For example, suppose you have a project named:

hello-codex

You can open multiple threads in this project:

Thread Task it represents
Thread 1 Build a homepage
Thread 2 Fix the issue where clicking the button does nothing
Thread 3 Optimize mobile styles
Thread 4 Help me write the README
Thread 5 Check whether the project has errors

A simple way to define them:

Project = one code folder
Thread = one specific task in this project

For example:

Project: Product cover generator
Thread 1: build the homepage
Thread 2: fix image upload failure
Thread 3: optimize mobile layout
Thread 4: write project documentation

Why have threads?

Different tasks are easier to handle separately.

If you put "build the homepage, fix bugs, change styles, write documentation" all into one conversation, Codex can easily confuse the context, and it is hard for you to check exactly what changed.

A better pattern is:

One clear task = one thread

For example, if you want to build a page:

Please help me build an AI tool introduction page.

This is one thread.

Later, if you find a problem with the button, open another thread:

Please check why the homepage button does not respond after clicking.

Summary:

A thread is a task conversation in Codex App; one thread handles one specific task.

Waiting for approval

When Codex executes tasks, it often needs the user to approve permissions.

A waiting-for-approval label also appears on the corresponding conversation.

Click the corresponding conversation, then click Allow, and Codex continues with the next steps.

Archive

Archive means setting aside a completed thread that you do not need to handle for now.

It does not delete or merge code. It only makes your task list cleaner.

For example, you have finished these tasks:

Thread 1: optimize mobile styles
Thread 2: build a homepage
Thread 3: build a homepage

Thread 2 and Thread 3 are complete, and you do not plan to use Thread 1 either, so you can archive these threads.

After archiving, they no longer occupy space in the current task list, so the project interface is cleaner.

To unarchive a conversation, find it in settings and restore it.

Permission controls
Sandbox

To understand permission controls, first understand the sandbox concept.

Think of it this way:

Codex can work inside the fence, but it cannot freely leave the fence and modify your computer.

Codex App is not an ordinary chat tool. It can read files, modify files, and run commands, so it needs a "fence" that limits where it can operate, whether it can connect to the network, and whether it can modify files outside the project. In the official documentation, Codex sandbox modes include read-only, workspace-write, and danger-full-access, which control filesystem and network access boundaries.

In simple terms

Suppose your project folder is:

D:\AI-Codex-Projects\hello-codex

If the sandbox is enabled, Codex normally works only within this project folder, for example:

It can view index.html
It can edit style.css
It can run npm run dev

These actions may require your approval:

Access desktop files
Read the Downloads folder
Modify files outside the project
Download things from the internet
Run high-risk commands

In short:

Sandbox = setting work boundaries for Codex
Three main permission levels

Request approval
Approve for me
Full access

The relationship works like this:

Option you see Relationship to Sandbox
Request approval Sandbox restrictions apply; it asks you before crossing boundaries
Approve for me Let the system automatically judge part of the approvals for you
Full access Removes sandbox limits, can perform any operation on the computer, and has the highest risk

Beginners should enable:

Request approval or automatic-approval options. For a first setup, choose a mode that keeps the project boundary closed. Let Codex work inside the current project, but require confirmation when it crosses boundaries, uses the network, or runs high-risk commands. Permission option names may differ across versions, but the core principle is the same: do not enable full access at the beginning.

One-sentence summary

Sandbox is Codex's safety fence.

It decides whether Codex can:

View files
Edit files
Access directories outside the project
Use the network
Run commands
Model selection
Reasoning effort

Reasoning effort has four levels. Higher levels provide stronger reasoning, but they take more time and use more tokens.

Option In simple terms Suitable tasks
Low Thinks less, runs fast, saves quota Change copy, change colors, small issues
Medium Balances speed and quality Ordinary web pages, simple bugs, everyday development
High Thinks more deeply; better for complex problems Multi-file changes, complex bugs, refactoring
Very high Most careful, slowest, uses the most quota Very difficult problems, architecture analysis, bugs that cannot be fixed after repeated attempts
Model selection

Here you can choose different models. Model capabilities, availability, and usage depend on account plan, region, version, and model catalog. For ordinary tasks, use the default recommended model. For complex tasks, consider switching to a stronger model or increasing reasoning effort.

Speed

Some models or versions provide service tiers such as standard / fast.

Fast mode speed, quota use, and availability all depend on what the current interface shows. Consider enabling it when a task is urgent and you have enough quota; you do not need to enable it by default for daily tasks.

Guidance

You can add guidance while a task is running.

If you notice that the AI has misunderstood your intent while it is running, do not let it continue. Provide guidance right away.

If you do not choose guidance, the request is queued. The AI runs your next request only after the previous task finishes.

Plan mode

When Plan mode is enabled, Codex does not start immediately. It first writes a work plan and starts only after you confirm it.

For complex tasks, enable Plan mode first so you can catch omissions.

Annotations

Annotations are in the upper-right area of the multifunction panel.

After you open a page with the built-in browser in Codex, the annotation feature becomes available.

Use it to ask the AI to modify only a specific part of the page.
