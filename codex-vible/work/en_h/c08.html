Skill

A prepared workflow for Codex.

Codex can read code, edit code, and run commands.

If you often ask it to do the same type of task, such as writing a README, doing a code review, generating a web page, or organizing documents, you can turn that process into a Skill.

What is a Skill?

Concept In simple terms
Skill A fixed way of working
Prompt The prompt for the current task
Workflow The process for completing the task
Template A reusable template
Instruction Long-term rules for Codex
Resource Reference materials included with the Skill
Script Optional automation scripts included with the Skill

For example, suppose you always want Codex to write a README that must include:

Project introduction
Installation steps
Startup commands
File structure
Frequently asked questions

Then you can create a README Skill.

After that, you do not need to explain the rules again each time. Invoke this Skill, and Codex follows that process.

Skill or MCP? Which should you use?

For the overall differences among plugins, Skill, and MCP, see the earlier summary table "How plugins, Skill, and MCP relate." This section answers the most common point of confusion: should a given need use Skill or MCP?

Use this rule: Use Skill for "how to do it"; use MCP for "which tool to connect to."

Your need Use Skill or MCP
Write a README or set a fixed document output format Skill
Do a code review or UI review Skill
Generate a landing page or standardize a bug fix process Skill
Look up the latest development documentation or new version APIs MCP
Connect to a database MCP
Read Figma designs MCP
Read GitHub issues / PRs MCP
Connect to Notion, an internal knowledge base, or internal company tools MCP

How is a Skill different from a normal prompt?

For a one-off task, write the prompt directly. For a task you repeat often, use a Skill.

Comparison dimension Normal prompt Skill
How it is used Entered manually each time Saved as a fixed capability
Stability Requirements are easy to miss More stable
Suitable scenarios Temporary tasks Repeated tasks
Reusability Low High
Content structure One prompt Instructions, templates, materials, scripts
Who it suits Everyone People who repeat the same type of task often

When is Skill suitable?

Situation Suitable for a Skill?
You often repeat the same type of task Suitable
You need to write a lot of rules every time Suitable
You want Codex output to be more stable Suitable
Multiple people on a team need to use the same process Suitable
A small one-time task Not necessarily needed
Temporarily changing one line of copy Not needed
Just asking about a concept Not needed

What does a Skill usually include?

Content Purpose
instructions Tells Codex how to do it
resources Stores reference materials, templates, and standards
scripts Optional scripts for handling tasks automatically
examples Example inputs and example outputs
checklist A checklist to avoid missing steps

Basic structure of a Skill

You can write a simple Skill like this:

# Skill name

## Suitable scenarios
What this Skill is suitable for.

## Work goal
What result Codex should ultimately deliver.

## Workflow
1. First analyze the input content
2. Then confirm the task type
3. Then process it according to fixed steps
4. Finally output the result and checklist

## Output format
Specify how Codex should output the final result.

## Notes
What must not be done, and which risks should be pointed out.

For example, a README Skill:

# README generation Skill

## Suitable scenarios
Used to generate a README document based on the current project.

## Work goal
Output a well-structured README suitable for beginners.

## Workflow
1. Read the project structure
2. Check package.json or the main entry file
3. Determine the project type
4. Generate the project introduction
5. Add installation steps and startup commands
6. Explain the file structure
7. Output frequently asked questions

## Output format
Use Markdown format.

## Notes
Do not invent features that do not exist.
Clearly mark anything uncertain.

How to add a Skill in Codex App

Adding a Skill in Codex App has two cases:

1. Use an existing Skill
2. Create your own Skill
Use an existing Skill

In the plugins Skill section, you can see several Skill items recommended by the system.

Create your own Skill

If you want to create a Skill yourself, use this in a Codex App thread:

$skill-creator

It works as a Skill creation assistant. It helps you organize a repeated process into a Skill.

Steps:

Step Action
1 Open Codex App
2 Select a project
3 Create a new thread
4 Enter $skill-creator
5 Tell it which Skill you want to create
6 Provide usage scenarios, rules, and example output
7 Have Codex generate the Skill file
8 Check the generated result
9 Use this Skill later in a new thread

Example prompt:

$skill-creator

Please help me create a README Skill.

Purpose of this Skill:
Automatically generate a README suitable for beginners based on the current project.

Trigger scenarios:
Use it when I say “generate README,” “write project instructions,” or “organize project documentation.”

Workflow:
1. First read the project structure
2. Check package.json, README, and entry files
3. Determine the project type
4. Generate a project summary
5. Write installation steps
6. Write startup commands
7. Explain the purpose of the main folders
8. Add frequently asked questions
9. Do not invent anything uncertain

Output format:
Use Markdown.

Must include:
- Project summary
- Features
- Installation steps
- Startup commands
- File structure
- Frequently asked questions
- Future optimization directions

How to add a Skill in Codex CLI

There are three main ways to add a Skill in Codex CLI:

1. Use an existing Skill
2. Use $skill-creator to create a Skill
3. Manually create a SKILL.md file
Three ways to add a Skill
Method Who it suits In simple terms Recommendation level
Use an existing Skill New users Call an existing Skill directly Recommended
Create with $skill-creator People who want to turn prompts into a Skill Have Codex organize the Skill for you Most recommended
Manually create SKILL.md People familiar with the file structure Write the Skill file yourself Advanced
Method 1: Use an existing Skill

After entering the project directory, start Codex CLI:

cd project-directory
codex

After Codex CLI opens, you can type:

/skills

Or enter:

$

Codex shows the available Skill items.

If you already know the Skill name, you can name it directly in the task:

Please use $readme-skill to generate a README based on the current project.

Or:

$ui-review-skill Please check the visual issues on the current homepage and provide suggestions for changes.
How to use existing Skill items
Usage Example Suitable scenario
/skills Open the Skill list When you do not know which Skill items are available
Enter $ Quickly select a Skill When you want to call one fast
$skill-name $readme-skill When you know the Skill name
Natural-language description Please use the README Skill to write project instructions When you do not know the exact name
Method 2: Use $skill-creator to create a Skill

To save a repeated process as a Skill, use:

$skill-creator

It works as a Skill creation assistant and asks:

Question Purpose
What this Skill does Make its purpose clear
When it should be triggered Make the applicable scenarios clear
Whether scripts should be included Determine whether it is only an instruction-type Skill
What the output format is Keep the result stable
What restrictions it has Avoid random changes, invented content, or arbitrary execution
$skill-creator workflow
Step Action Purpose
1 Enter the project directory Make sure the Skill is generated in the correct project
2 Run codex Open Codex CLI
3 Enter $skill-creator Start the Skill creation assistant
4 Describe the Skill purpose Tell it what to do
5 Add trigger scenarios Tell it when to use the Skill
6 Add the workflow Set Codex’s execution steps
7 Add the output format Keep the result stable
8 Check the generated result Confirm whether SKILL.md is reasonable
9 Reopen or continue using it Test whether the Skill works

2. Check package.json, README, and entry files
3. Determine the project type
4. Generate a project summary
5. Write installation steps
6. Write startup commands
7. Explain the purpose of the main folders
8. Add frequently asked questions
9. Do not invent anything uncertain

Use Markdown.

Must include:
- Project summary
- Features
- Installation steps
- Startup commands

Method 3: Manually create a Skill file

A Skill is a folder that must contain:

SKILL.md

The simplest structure is:

.agents
└── skills
    └── readme-skill
        └── SKILL.md

You can also include scripts, reference materials, and resource files:

.agents
└── skills
    └── readme-skill
        ├── SKILL.md
        ├── scripts
        ├── references
        └── assets
Skill file structure description
File / folder Required? Purpose
SKILL.md Required Write the Skill name, description, and specific instructions
scripts/ Optional Store executable scripts
references/ Optional Store reference documents, standards, and instructions
assets/ Optional Store templates, images, and resource files
A minimal SKILL.md example
---
name: readme-skill
description: Use when the user needs to generate a README, project instructions, installation tutorial, or startup steps.
---

You are a README document generation assistant.

Task:
Generate a README suitable for beginners based on the current project.

Workflow:
1. Read the project structure
2. Check package.json, README, and entry files
3. Determine the project type
4. Generate the project introduction
5. Write installation steps
6. Write startup commands
7. Explain the file structure
8. Add frequently asked questions
9. Do not invent anything uncertain

Output format:
Use Markdown.

Must include:
- Project summary
- Features
- Installation steps
- Startup commands
- File structure
- Frequently asked questions
- Future optimization directions

How to use a Skill after adding it

After adding a Skill, you usually use it in one of two ways:

Usage Example
Explicitly specify the Skill Please use $readme-skill to generate a README
Let Codex decide automatically Help me write a project README

A clear Skill description helps Codex decide automatically when to use it.

For example:

description: Use when the user needs to generate a README, project instructions, installation tutorial, or startup steps.

This description is clear.

Do not write it too vaguely:

description: Help me write things.

Codex will not know when to invoke it.

Where should you put Skill items?

Location Suitable scenario In simple terms
.agents/skills in the project Only for the current project Project-specific Skill
User-level Skill directory You want to use it across multiple projects of your own Personal general-purpose Skill
Team / administrator configuration Team members use it uniformly Team-shared Skill
Inside a plugin You want to package and distribute it for others to install Official capability package
